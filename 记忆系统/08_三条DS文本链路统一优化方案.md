# 三条 DS 文本链路统一优化方案

日期：2026-04-23  
适用范围：

- 北周计谋回报页的“追问后的最终回批”
- 南陈女帝回信 / 回批
- 冯道之 AI 军师代拟

这份方案采用我们刚刚确认的 **方案 B**：  
不是继续零散给每条 prompt 加上下文，而是统一抽出一套“文本生成思路”，再分别为三条链路补各自的输出矩阵与上下文结构。

---

## 一、这次优化的目标

这次不是为了让 AI “知道更多”，而是为了让它：

1. 更像一个**具体的人**
2. 站在一个**具体的位置**
3. 对一个**具体局面**
4. 说出一段**更像当下会说的话**

所以这轮优化的重点，不是简单扩充背景材料，而是把“上下文信息如何被裁剪、如何影响输出方向”做得更清楚。

如果只用一句话概括这次目标：

- 北周“追问后的最终回批”要像**同一段对话的自然收束**
- 女帝回批要像**真正的统治者批语**
- 冯道之代拟要像**真正替玩家裁剪策略的谋士**

---

## 二、为什么不能继续用“哪里缺就补哪里”的方式修

当前三条链路已经都能生成文本，但问题在于它们各自长得不一样：

- 北周追问最终回批偏像“补一句”
- 女帝回批偏像“题目讲评”
- 冯道之代拟偏像“拿着很多资料润色一句话”

这些问题的共同根源，不在于 AI 模型本身，而在于：

- 三条链路吃到的上下文层级不统一
- 三条链路的“人物位置感”强弱不同
- 三条链路的“输出目标”没有被提前结构化

所以如果继续沿用旧做法，只会变成：

- 追问补几句上下文
- 女帝再补几句上下文
- 冯道之再补几句上下文

最后仍然是三套各修各的 prompt。

这次我们要改的是这个问题：  
让三条文本链路都遵守同一套生成逻辑，但又保留各自鲜明的输出目标。

---

## 三、统一设计原则

### 原则 1：共享“生成思路”，不共享“整段 prompt 文本”

我们不打算把三条链路做成一个大而全的通用 prompt。

原因很简单：

- 北周追问的目标是“把一段正在发生的对话收住”
- 女帝回批的目标是“以统治者视角写密批”
- 冯道之代拟的目标是“替玩家拟计”

这三件事的文体、节奏、关注点都不一样。  
如果硬塞进一套大 prompt，只会让每一条都变钝。

所以共享的是：

- 信息分层思路
- 上下文裁剪方式
- 输出矩阵的设计方法

而不是共享同一段 system prompt。

### 原则 2：上下文不是越多越好，而是越“有方向”越好

这三条链路都已经不缺信息了。  
真正缺的是：

- 哪些信息要优先被看见
- 哪些信息只作为底噪存在
- 当前这一段文本，究竟要解决什么问题

所以这轮每条链路都要补一张“输出目标卡”。

### 原则 3：同一条链路内部，也要区分“背景层”和“裁剪层”

例如：

- “本回合局势”属于背景层
- “这一手现在最应该打哪一层数值”属于裁剪层

背景层回答的是“现在发生了什么”。  
裁剪层回答的是“在这些事情里，这一段话最该抓什么”。

只有把两层分开，生成出来的文本才会像真正在局中的人，而不是信息摘要器。

### 原则 4：矩阵定方向，不定句式

这一条和我们在北周 NPC 计谋反应矩阵里采用的原则一致。

矩阵只规定：

- 此刻该偏什么情绪
- 该出现什么动作
- 该回到哪一层结构
- 应该说长还是说短

但不规定固定台词。  
这样才能保持生成活性，不会几轮之后被玩家读出模板味。

### 原则 5：上下文注入要有预算意识

三条链路后续都会增加上下文，如果不提前立预算原则，很容易出现 prompt 越堆越厚、真正有用的信息反而被埋掉的问题。

所以后续实现时，统一采用三档注入原则：

- **全文注入**
  只给当下性最强、必须保真进入 prompt 的信息，例如：
  - 当前回合事件
  - 本次计谋类型
  - 玩家追问 / 补答原文
  - 角色声音档案核心字段
- **摘要注入**
  对背景性信息先做系统压缩，再以 1-2 句自然语言注入，例如：
  - 长期记忆
  - 关系记忆
  - 上回往来
  - 派系压力
- **按需注入**
  只在相关窗口或相关情境下注入的信息，例如：
  - 战役窗口信息
  - 高压偏移
  - 高风险回合的生存压力

这条原则的目的不是省 token 本身，而是保证 prompt 的前几屏永远是“现在最该看的东西”。

---

## 四、统一上下文框架

三条链路统一按五层上下文来理解。

### 1. 时局层

这一层只回答：

- 现在是第几回合
- 本回合主要事件是什么
- 当前大的政治天气是什么
- 是否处于战役窗口
- 是否处于高压、转折或残局状态

这层的作用是给文本提供“天气”。

### 2. 关系层

这一层回答：

- 玩家和目标人物上回怎么碰过
- 近两回合关系温度怎样
- 当前是更接近信任、试探、戒备还是敌意
- 这段话是不是发生在“刚刚挨过一刀”之后

这层决定语气软硬和愿不愿意松口。

### 3. 结构层

这一层回答：

- 本次动作击中了哪一层结构
- 是个人值在动，还是派系值在动
- 是地方军头三值在动，还是国力五维在动
- 如果是追问，则补答到底修正了哪一层

这层决定文本不只是“像”，还要“说得准”。

### 4. 记忆层

这一层回答：

- 目标人物记不记得玩家过去做过什么
- 他记不记得和另一个 NPC 的旧账
- 他最近得势还是吃亏
- 他是不是正在被夹压

这层决定文本有没有连续感。

### 5. 声音层

这一层回答：

- 这个人本来像谁
- 当前应当偏什么反应方向
- 在高压状态下，他的声音会怎么偏
- 允许他说到哪一步
- 建议说多长

这层决定文本像不像这个人。

这五层是**上下文信息的分类框架**，用于组织“给模型看什么”。  
它不替代北周 NPC 回应目前已经建立起来的那套表现顺序：

**人物声音 -> 计谋反应 -> 高压偏移 -> 关系远近与记忆 -> 动态结算结果**

两套框架的关系是：

- 五层上下文框架决定“信息如何分类、如何注入”
- 北周现有五层叠加顺序决定“生成时优先表现什么”

也就是说，后续如果我们优化北周追问最终回批，不是要推翻北周已有的分层，而是让它在**同一套表现顺序**下，吃到更完整、更有方向的上下文。

## 五、三条链路当前的缺口

### 1. 北周“追问后的最终回批”

当前这条链路已经接进了：

- 声音档案
- 计谋反应矩阵
- 高压偏移
- 原始计谋类型
- NPC 追问
- 玩家补答
- follow-up parse evidence

但它最关键的缺口在于：

- 它没有把“原始北周 NPC 回应那一套完整动态上下文”接续回来
- 所以它更像是“另起一段收尾”，而不是“顺着刚才的心理状态继续说”

现在它更像：

- 我知道你刚补了什么
- 我知道你刚答得好不好

但它还不够像：

- 我还记得我们刚才是在什么局里对话
- 我还带着上一段的情绪和判断在往下说

### 2. 南陈女帝回批

当前这条链路吃到的信息很少：

- 来源回合
- 题目
- 选项
- 玩家附言
- effect summary

这能让它“有回批”，但还不足以让它“像女帝”。

它目前缺少的是：

- 当前南陈整体国势的统治者视角
- 当前北方局势对她决策的反照
- 她为什么此刻更急某一维
- 她对萧宝颖现在处境的体恤、利用或防备

所以现在的女帝回批容易像：

- 朕采纳了什么
- 朕担心什么

但还不够像：

- 一个真正知道自己在和时间赛跑的统治者写给北方暗桩的密批

### 3. 冯道之 AI 军师

冯道之目前已经吃了相当丰富的上下文：

- 本回合局势
- 战局摘要
- 目标本回合公开表态
- 上回往来
- 关系温度
- 近来得失
- 派系压力
- 长期旧账
- 关系旧账
- 玩家危险等级
- 已解锁暗线

所以他现在的问题不是“信息少”。  
问题是：

- 缺一层明确的“谋士策略裁剪”

也就是说，他知道很多，但系统还没有先告诉他：

- 这一手现在最该打什么
- 最好的切口是什么
- 最危险的红线是什么
- 此刻应当写成“顺推、借势、递刀、留后手”里的哪一种

所以他目前更像：

- 帮你写一句更像样的话

而不是：

- 真正替你判断这回合该怎么落笔

## 六、北周“追问后的最终回批”设计方案

### 1. 定位

这条链路不是独立回复，而是：

**原始 NPC 回应的收束版续写**

它要做的不是重新生成一个新态度，而是把原本已经抬起来的情绪、判断和口风，顺着玩家补答，推到一个新的停点。

### 2. 上下文策略：透传 + 增量

追问最终回批不是一条重新设计的新链路，而应被视作：

**原始北周 NPC 回应上下文的完整继承 + 追问场景的增量叠加**

因此后续实现时，建议直接把原始 NPC 回应生成时已存在的动态上下文**原样透传**进来，包括但不限于：

- `round`
- `eventName`
- `eventBriefing`
- `previousDealings`
- `relationshipTemperature`
- `recentCourtFortune`
- `factionPressure`
- `longTermMemorySummary`
- `relationMemorySummary`
- `relatedNpc`
- `northParse`

在此基础上，再叠加四个追问专属增量字段：

- `followUpResultTone`
- `clarifiedConcern`
- `remainingSuspicion`
- `closureMode`

这样后续实现时，重点不是“再造一套字段”，而是保证：

- 原始回应时看到的完整局面不要在追问链路里丢失
- 追问阶段只额外补进“这句补答改变了什么”

### 3. 建议新增的裁剪字段

这几项不必原样暴露给模型名词，可以先由系统总结成自然语言：

- 这句补答主要澄清了什么  
  例如：动机、执行路径、收益归属、暴露风险、忠诚疑虑

- 这句补答主要哪里没压住  
  例如：仍像借刀、仍像替对手探路、仍像空口大话

- 这次最终收束应属于哪类  
  - 收了疑，但未尽信
  - 表面揭过，暗里记账
  - 暂时信你，顺手给一步
  - 越描越黑，疑心更深

### 4. 建议新增的“最终回批矩阵”

矩阵输入维度建议包括：

- 原始计谋类型
- 玩家补答质量：高 / 中 / 低
- 当前关系温度：软 / 摇摆 / 硬
- 当前高压状态：低 / 中 / 高

矩阵输出方向建议包括：

- 情绪收束方向
- 是否翻旧账
- 是否还给半句台阶
- 是否加深防备
- 收束长度建议

### 5. 想达到的效果

玩家会感觉：

- 这不是另一个系统在补一句结算说明
- 而是刚才那个 NPC，听完你的补答之后，顺着自己的性格和处境，把这场对话收住了

## 七、南陈女帝回批设计方案

### 1. 定位

这条链路的目标不是“反馈题目做得对不对”，而是：

**以女帝陈倩的统治者视角，写给萧宝颖的密批**

它应该同时带出三层东西：

- 她如何处置这一题
- 她对当前南陈局势怎么看
- 她对萧宝颖此刻这个人的位置怎么看

### 2. 先补一份轻量声音档案

在进入矩阵和上下文层之前，女帝需要先有一层稳定的“人物底色”。  
不然即使矩阵方向正确，最后生成出来的也更像一段聪明的批语，而不像陈倩本人。

这份声音档案不必像北周 10 位 NPC 那么重，但至少应定义：

- 自称基线
  - 以“朕”为主，是否在特定密批语境下偶尔转为更缓的自指
- 句式特征
  - 偏短促决断，还是偏从容铺展
  - 是否习惯用判断句收束
- 用词气质
  - 偏文雅 / 务实 / 冷厉中的哪一种组合
  - 是否保留南朝文风
- 对萧宝颖的称呼与口吻基线
  - 是更亲近、更期许，还是更偏利用与审度
- 高压偏移
  - 国势危急时，她是更短、更冷，还是更稳、更压住情绪

这层的作用不是增加信息量，而是保证后面的矩阵和上下文都“落在她这个人身上”。

### 3. 新增上下文字段

在现有的题目、选项、附言、effect summary 之外，建议补入：

- 当前南陈国势摘要
  - 最弱维度
  - 最强维度
  - 刚见成色的维度
- 当前北方局势摘要
  - 本回合北方事件
  - 是否进入战役窗口
  - 北周当前风向是更乱还是更稳
- 玩家状态摘要
  - 萧宝颖当前处境是否高压
  - 女帝此时应更安抚还是更催逼
- 问政结构摘要
  - `policyParse` 的简化结论
  - 此次附言是切中焦点、偏空、还是有副作用风险
- 政务领域
  - 军事 / 财政 / 吏治 / 民生 / 外交
  - 这项信息不应从 `policyParse` 推出，而应来自问政题本身的题目元数据
- 问政连续性摘要
  - 是否存在上一回合问政余波
  - 女帝这次是在“顺着走”，还是“纠偏”

### 4. 建议新增的“女帝回批矩阵”

矩阵输入维度建议包括：

- 附言质量：高 / 中 / 低
- 是否切中本题焦点
- 政务领域：军事 / 财政 / 吏治 / 民生 / 外交
- `legitimacyTone`：up / steady / down
- 当前南陈最弱维度
- 当前是否处于战役窗口
- 玩家当前风险等级

矩阵输出方向建议包括：

- 批语温度：嘉许 / 克制认可 / 审慎采用 / 明用暗防
- 国家重心：守成 / 财用 / 吏治 / 战备 / 民生
- 对玩家语气：亲近 / 期许 / 提醒 / 轻压
- 结尾动作：留后手 / 提醒代价 / 督促下回继续补

### 5. 想达到的效果

玩家应该读到：

- 她不是一道问答机
- 她是一个知道自己在有限时间里，要把江南攒成什么样子的统治者

同样一条好附言，在不同局面下，她的回批应当不同：

- 有时是欣然采纳
- 有时是采纳，但明显留手
- 有时是认你的方向，不认你的节奏

## 八、冯道之 AI 军师设计方案

### 1. 定位

冯道之不是“替玩家润色”，而是：

**在玩家已知信息范围内，替玩家裁剪最值得下手的一刀**

所以这条链路最需要补的，不是更多时局资料，而是一层更清楚的“谋士策略卡”。

### 2. 先明确冯道之的信息边界

这里要提前做一个明确设计决策，否则后面越做越容易让玩家觉得他在“开天眼”。

本方案建议采用：

**路线 A：冯道之是情报能力强于玩家、但仍有盲区的老谋士**

也就是说：

- 他可以吃到系统根据当前局面翻译出的**模糊战略判断**
- 但不能直接吃到精确数值、精确阈值或未解锁暗线

例如后续即使系统判断某人已经接近“可再压一步”的危险边缘，喂给冯道之的也不应是：

- “皇帝恩宠还剩 0.3，离阈值差 0.1”

而应翻译成更像谋士判断的话：

- “此人在御前的庇护已经很薄，再压一两回，恐怕就撑不住”

这样可以同时保住两件事：

- 冯道之仍然有策略价值
- 冯道之又不会显得知道玩家不该知道的系统精算结果

### 3. 新增上下文字段

建议在现有上下文上，再补四类裁剪信息：

#### 1. 当前最该打哪层

例如：

- 信任
- 暗线
- 皇帝恩宠 / 太后眷顾
- 派系值
- 忠诚 / 军力
- 战役准备

#### 2. 当前最佳切口

例如：

- 顺着对方私利
- 顺着公开表态反手一拧
- 顺着最近得失下手
- 顺着旧账翻案
- 顺着战役窗口落笔

#### 3. 当前最该避开的红线

例如：

- 太露骨
- 太像替对手探路
- 太早摊牌
- 太空泛
- 太像在说大话

#### 4. 当前谋士输出模式

建议先定义成六类：

- 探路
- 顺推
- 借势
- 递刀
- 收口
- 留后手

这六类模式在实现前应先补成明确的定义：

| 模式 | 定义 | 典型触发场景 |
| --- | --- | --- |
| 探路 | 代拟重心是摸清对方真正介意什么，语气偏试探、留余地 | 信任不足、暗线不足、对方态度未明时 |
| 顺推 | 代拟重心是顺着对方已有松口往下走，不主动加压 | 对方已有松动、关系温度偏软时 |
| 借势 | 代拟重心是把本回合局势中的一件事挂到对方利益或恐惧上 | 本回合事件、朝堂风向或战区变化可利用时 |
| 递刀 | 代拟重心是给出一把可执行的由头，让对方能顺势动手 | 某条处置链、离心链或结构链已接近阈值时 |
| 收口 | 代拟重心是巩固已有成果，此回合不再加码 | 已有推进、但当前风险较高或收益已够时 |
| 留后手 | 代拟重心是有意识留退路，不把话说满 | 时机未到、对方摇摆、或玩家当前危险偏高时 |

### 4. 建议新增的“冯道之输出矩阵”

矩阵输入维度建议包括：

- 计谋类型
- 目标角色类型：朝堂 / 外部军头 / 混合型外部角色
- 玩家危险等级
- 当前是否处于战役窗口
- 是否已解锁足够暗线

矩阵输出方向建议包括：

- 输出模式
- 语气轻重
- 是否应更重“利人”还是更重“害国”
- 是否应直说还是留半步
- 是否应强调战区、派系还是个人利益

### 5. 想达到的效果

冯道之生成的内容应当让玩家感觉：

- 这是在替我做判断
- 不是单纯把一句话写得更顺

同样是 `献策`，他应该知道：

- 这回合是替我养人
- 还是替我害国
- 还是替我给后面某条链埋钩子

同样是 `谶纬`，他也应该知道：

- 是更该重“名分裂缝”
- 还是更该重“中枢可执行抓手”

## 九、三套专属矩阵的分工

为了避免三条链路以后越做越像，这里提前明确它们的矩阵分工。

### 1. 北周追问最终回批矩阵

重点解决：

- 这段对话怎么收
- 收到什么情绪停点
- 对玩家的口风更软还是更硬了

它关注的是：**对话收束**

### 2. 女帝回批矩阵

重点解决：

- 她站在哪个国家位置上批这件事
- 她怎么看当前南北局势
- 她对萧宝颖此刻更倚重还是更提醒

它关注的是：**统治者批政**

### 3. 冯道之输出矩阵

重点解决：

- 这一手现在最该打哪层
- 最好的切口是什么
- 最该避开什么

它关注的是：**谋士裁剪**

## 十、推荐落地顺序

### 第一阶段：先做设计落地，不急着上代码

这一阶段只做文档和上下文字段定义。

建议产出：

1. 三条链路的 context schema
2. 三套矩阵的草稿
3. 三条链路现状 vs 目标的对照表

### 第二阶段：第一批优先做“冯道之 + 追问”，第二批再做女帝

建议优先级写成两层：

#### 第一批

- 冯道之 AI 军师
- 北周“追问后的最终回批”

如果资源允许，建议并行推进。  
如果必须串行，从**工程复用与风险控制**看，先做北周追问也依然合理；但从**玩家触达率与体感收益**看，冯道之前置也很有价值。

#### 第二批

- 南陈女帝回批

推荐这样排的原因是：

- 冯道之触达率最高，玩家最容易感受到提升
- 北周追问链路最贴近现有北周 NPC 体系，技术复用最多
- 女帝链路最独立，也最适合先把声音档案和矩阵打稳后再统一落地

### 第三阶段：补测试

建议至少覆盖三类测试：

1. prompt wiring test  
   确认新的上下文字段真的接入了 prompt

2. matrix behavior test  
   确认不同链路的输出方向被区分开

3. fallback parity test  
   确认 DS 不可用时，本地 fallback 仍满足：
   - 保留角色自称，不退化为系统第三人称
   - 仍有情绪方向或立场倾向，而不是中性客观陈述
   - 输出长度不低于正常输出的大约 60%

## 十一、实施时的限制条件

### 1. 不给任何一条链路开天眼

这条原则对三条链路都适用：

- 北周追问最终回批不能知道玩家不知道的系统层事实
- 女帝回批不能突然知道北周密室里的隐情
- 冯道之不能比玩家多知道未解锁暗线

### 2. 不把矩阵做成模板库

矩阵只能定义方向和边界，不能变成固定句库。  
否则文本会很快变得机械。

### 3. 先保证“像谁”，再追求“会写”

如果一条回批很漂亮，但不像这个人，那就不算成功。  
人物位置感始终优先于修辞。

### 4. 输出长度要被当成角色行为的一部分

以后不能只问“够不够长”，而要问：

- 这个人按他的身份、关系、局势，此刻会不会说这么多
