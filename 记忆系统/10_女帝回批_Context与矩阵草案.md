# 女帝回批 Context 与矩阵草案

日期：2026-04-23  
适用对象：回合结算页中，由 DS 生成的南陈女帝陈倩回批

---

## 一、这份底稿解决什么问题

女帝回批当前已经能生成“像回批”的内容，但还不够“像陈倩”。

它目前更像：

- 对问政题的讲评
- 对玩家附言的简短反馈

它还不够像：

- 一个南朝统治者在有限时间内排国势、压局面、用北方暗桩时写下的密批

所以这条链路的核心目标不是“让她知道更多”，而是让她同时站稳三层位置：

1. 她是南陈统治者
2. 她正在处理一道具体政务题
3. 她是在对萧宝颖这个人写批语

---

## 二、当前链路的真实状态

当前 `buildEmpressFeedbackPrompt` 实际吃到的信息很少，核心只有：

- 来源回合
- 题目母题
- 采纳选项
- 玩家附言
- effect summary

这套输入足够让模型知道“你在回批什么”，但还不够让模型知道：

- 此时南陈最急的是什么
- 北方局势怎样影响她的批语
- 她此刻对萧宝颖是更安抚、更寄望，还是更提醒
- 她写的是“政务批语”，还是“密信中的批语”

因此，下一步不是简单补句式，而是补齐：

- 女帝的声音底色
- 统治者视角的时局上下文
- 问政题领域差异
- 她对玩家的态度基线

---

## 三、链路定位

这条链路的正式定位建议写成：

> 女帝回批不是“题目讲评”，而是女帝陈倩写给萧宝颖的一段密批。

它的职责是同时写出三层东西：

1. 朕如何处置这一题
2. 此举先会在哪一层见效
3. 朕仍担心什么、留了什么后手

它**不负责**：

- 直接复述数值
- 变成天道式总结
- 告诉玩家她知道了玩家不该知道的北周密事

---

## 四、先补女帝的轻量声音档案

在补上下文和矩阵之前，女帝必须先有“底色”。

否则矩阵再精细，最后生成出来的仍会更像一条聪明回复，而不是陈倩本人。

### 1. 建议最少定义的字段

| 字段 | 建议定义内容 |
| --- | --- |
| 自称 | 以“朕”为主 |
| 句式特征 | 偏收束、判断句强，不宜过分铺陈 |
| 用词气质 | 文雅中带务实，不浮、不躁、不散 |
| 对萧宝颖的口吻基线 | 既有期待，也带审度，不是纯亲近 |
| 高压偏移 | 国势紧时，语气更短、更稳、更有压制力 |

### 2. 推荐的基础方向

- 她不应像北周权臣那样满嘴试探、递刀、翻旧账
- 她也不应像天道判词那样抽象总结
- 她更像：
  - 把事情先定下来
  - 把代价先看见
  - 把话说到够你明白，但不完全说透

### 3. 想达到的声音效果

玩家一读就能感觉：

- 这是一位统治者
- 这是一位在压住南陈局面的统治者
- 她对萧宝颖既有使用，也有分寸

---

## 五、Context Schema：现有输入与目标输入

### 1. 当前已有输入

| 字段 | 用途 |
| --- | --- |
| `sourceRound` | 回批来自第几回合 |
| `topic` | 题目母题 |
| `optionLabel` | 采纳选项标识 |
| `optionContent` | 采纳选项内容 |
| `reason` | 玩家附言 |
| `effectSummary` | 本次问政带来的实际变化摘要 |

### 2. 目标输入：新增层级

#### A. 问政题本体层

- `question`
- `optionLabel`
- `optionContent`
- `reason`
- `effectSummary`

#### B. 问政结构判断层

- `legitimacyTone`
- `focusMatched`
- `scoringFocus`
- `policyParse` 的简化摘要

这里的重点不是把 parse 原始分数塞进去，而是翻译成一句玩家和模型都能读懂的话。  
例如：

- “附言切题，且对代价有交代”
- “附言方向不错，但落地路径偏空”

#### C. 政务领域层

这次建议明确加一条：

- 政务领域：军事 / 财政 / 吏治 / 民生 / 外交

注意：

这项信息**不应从 `policyParse` 推出**。  
更合适的来源是：

- 问政题配置本身
- 或额外补一个题目元数据字段

因为这本来就属于题目设计信息，而不是附言解析结果。

#### D. 南陈统治者视角层

- 当前最弱维度
- 当前最强维度
- 最近刚起色的维度
- 是否仍在承受上一回合问政余波

#### E. 北方镜像层

- 当前北方事件
- 当前是否已进入战役窗口
- 北周当前是更乱还是更稳

#### F. 玩家位置层

- 萧宝颖当前危险等级
- 此时应更安抚还是更催逼

## 六、女帝回批矩阵草案

这套矩阵要解决的是：

**同样一条附言，在不同局势里，女帝为什么会批得不一样。**

### 1. 输入维度

| 维度 | 建议取值 |
| --- | --- |
| 附言质量 | 高 / 中 / 低 |
| 是否切中本题焦点 | 是 / 否 |
| 政务领域 | 军事 / 财政 / 吏治 / 民生 / 外交 |
| `legitimacyTone` | up / steady / down |
| 当前南陈最弱维度 | 财政 / 粮赋 / 军事 / 社会秩序 / 治理 |
| 当前是否处于战役窗口 | 是 / 否 |
| 玩家危险等级 | safe / under_watch / threatened 等 |

### 2. 输出方向

| 输出项 | 说明 |
| --- | --- |
| 批语温度 | 嘉许 / 克制认可 / 审慎采用 / 明用暗防 |
| 国家重心 | 守成 / 财用 / 吏治 / 战备 / 民生 |
| 对玩家语气 | 亲近 / 期许 / 提醒 / 轻压 |
| 结尾动作 | 留后手 / 提醒代价 / 督促继续补 |
| 长度建议 | 偏短 / 正常 |

### 3. 典型组合

#### `附言高质量 + 切题 + 财政题 + 当前最弱维度正好是财政`

- 更容易出现“嘉许 + 立刻采用”
- 批语会更偏务实
- 更容易写“此事先从财用处见效”

#### `附言高质量 + 军事题 + 当前处于战役窗口`

- 更容易出现“认可，但强调节奏与代价”
- 不宜只写采纳，还应写出她为什么急、又为什么不能躁进

#### `附言一般 + 切题不足 + 吏治题`

- 更容易出现“方向未必全错，但仍需收束”
- 可能认方向、不认节奏
- 更适合“克制认可”而非直接嘉许

## 七、建议新增的中间摘要

为了避免 prompt 太散，建议系统先产出几条自然语言摘要，再送进模型。

### 1. 附言质量摘要

例如：

- “这条附言切中题眼，也把代价交代得较清。”
- “这条附言方向尚可，但落地路径偏空。”

### 2. 女帝当前国家重心摘要

例如：

- “南陈眼下最急的是财用，不宜空谈大策。”
- “眼下虽当重战备，但仍要防朝内空耗。”

### 3. 女帝对玩家语气摘要

例如：

- “此时更宜稳住萧宝颖，不宜施压过重。”
- “此时可略加催逼，让他知道此事不可再拖。”

---

## 八、Fallback 设计要求

女帝 fallback 不能变成“系统默认说明”。

最低要求应满足：

1. 仍使用女帝自称
2. 仍有明确处置态度
3. 仍像密批，而不是结果播报
4. 输出长度不低于正常输出的大约 60%

建议 fallback 至少区分三种方向：

- 明显认可
- 采用但留后手
- 未附言时的自定裁断

这样即便没有 DS，玩家仍能感觉这是“女帝回批”，而不是一条默认字符串。

---

## 九、测试建议

### 1. prompt wiring test

确认新增内容真的进入 prompt：

- 女帝声音档案核心字段
- 政务领域
- 南陈国势摘要
- 北方镜像摘要
- 玩家危险等级

### 2. matrix behavior test

确认同样是“高质量附言”，在不同政务领域和不同国家重心下，输出方向会变化。

### 3. ruler-position test

确认回批始终像统治者，而不是像普通 NPC 或天道说明。

### 4. fallback parity test

确认 fallback 仍满足：

- 有“朕”
- 有决断
- 有立场
- 长度合格

---

## 十、这份底稿想达到的玩家效果

玩家最终应感到：

- 这不是对题目的讲评
- 而是一个知道自己在赶时间、在排国势、在用人的统治者，真正批了我这一笔

如果这个效果成立，女帝回批才会从“系统点缀”变成真正的人物文本资产。
