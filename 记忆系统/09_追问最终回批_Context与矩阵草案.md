# 追问最终回批 Context 与矩阵草案

日期：2026-04-23  
适用对象：北周计谋回报页中，NPC 发出追问后，玩家补答，再由 DS 生成的“最终回批”

---

## 一、这份底稿解决什么问题

这条链路的目标，不是让 NPC “再补一句话”，而是让玩家感觉：

- 自己刚才那场对话还在继续
- NPC 不是重开了一条新回复，而是在延续上一段态度
- 玩家的补答，确实改变了 NPC 的疑心、松口、记账或收口方式

换句话说，这条链路要解决的是：

**同一段对话，如何自然收束。**

---

## 二、当前链路的真实状态

当前 `buildNpcFollowUpFinalPrompt` 已经会吃到这些信息：

- NPC 身份
- 计谋类型
- 原始玩家说辞
- NPC 追问
- 玩家补答
- follow-up parse evidence
- 声音档案
- 计谋反应矩阵
- 高压偏移

所以它已经不是“完全空白”的二次回复。  
但它仍然有一个关键缺口：

**原始北周 NPC 回应生成时那套动态上下文，没有被带进来。**

这会直接造成两种体感问题：

1. 最终回批像“补一条答复”，不像“同一场对话的尾声”
2. NPC 会继续像这个人说话，但不像“刚才那个处在特定局面里的这个人”

因此，这条链路后续不是重新发明一套上下文，而是要改成：

**透传原始上下文 + 叠加追问增量**

---

## 三、链路定位

这条链路的正式定位应写成：

> 追问最终回批是“原始 NPC 回应的收束版续写”，不是独立的第二次完整回应。

它的职责只有三件事：

1. 接住原始回复已经抬起来的情绪
2. 评估玩家补答是否压住了疑点
3. 给这场对话一个符合人物和局面的停点

它**不负责**：

- 重新评估原始说辞的基础强度
- 改写本回合计谋结算
- 再发一个新的追问

---

## 四、Context Schema：透传部分

这一部分不是新发明的字段，而是原始北周 NPC prompt 已有上下文的完整继承。

建议完整透传的字段如下：

| 字段 | 用途 |
| --- | --- |
| `round` | 说明这段对话发生在第几回合 |
| `eventName` | 告诉 NPC 这场对话处在哪个事件下 |
| `eventBriefing` | 给出本回合局势天气 |
| `previousDealings` | 带回和玩家的上一轮往来 |
| `relationshipTemperature` | 说明双方当前是偏软、摇摆还是偏硬 |
| `recentCourtFortune` | 说明 NPC 最近得势还是吃亏 |
| `factionPressure` | 说明 NPC 现在受哪边压力最大 |
| `longTermMemorySummary` | 带回旧账、旧印象 |
| `relationMemorySummary` | 带回 NPC 与其他人的旧账 |
| `relatedNpc` | 若原计谋涉及第二目标，必须透传 |
| `northParse` | 带回本次原说辞真正打中的结构方向 |

这部分的原则是：

- 不重新设计
- 不拆成第二套命名
- 不在追问链路里丢失

---

## 五、Context Schema：追问增量部分

这一部分才是追问链路真正新增的内容。

### 1. 结构化增量字段

| 字段 | 说明 |
| --- | --- |
| `followUpResultTone` | 这次补答总体上是止血、稳住、加深疑心，还是把局面说坏 |
| `clarifiedConcern` | 玩家主要澄清了哪一类顾虑 |
| `remainingSuspicion` | 即便补答之后，NPC 还剩什么疑心 |
| `closureMode` | 这次最终回批应按什么方式收束 |

### 2. 建议的取值方向

#### `followUpResultTone`

- `stabilized`：补答明显止血，NPC 愿意往下接
- `partial_relief`：补答压住了一部分，但仍留尾巴
- `noisy`：补答信息很多，但没有压住关键点
- `worsened`：越描越黑

#### `clarifiedConcern`

建议先按这几类归纳：

- 动机
- 执行路径
- 收益归属
- 暴露风险
- 忠诚疑虑
- 站队疑虑

#### `remainingSuspicion`

建议是 1 句自然语言，不追求分类齐整，只追求让模型看得懂。  
例如：

- “仍像借刀”
- “仍像替对手探路”
- “仍不像能落地”
- “仍担心你话里另有图谋”

#### `closureMode`

建议先定成 4 类：

- 收了疑，但未尽信
- 表面揭过，暗里记账
- 暂时信你，顺手给一步
- 越描越黑，疑心更深

## 六、系统裁剪层：建议增加的中间摘要

这里的核心思路是：

**不要把 parse 原始分数直接塞给模型，而是先翻译成一两句自然语言。**

建议系统先产出这三条摘要，再送进 prompt：

### 1. 本次补答主要澄清了什么

例如：

- “这句补答把收益归属说清了，不再像空口邀功。”
- “这句补答主要压住了暴露风险，但仍未说清执行路径。”

### 2. 本次补答主要哪里没压住

例如：

- “你仍像借他之手动旁人的局。”
- “你把缘由说得更细了，但仍没有把代价说透。”

### 3. 这次回批应收在哪种情绪停点

例如：

- “可收口，但不宜显得立刻尽信。”
- “应保留台阶，同时让 NPC 暗里记账。”
- “应转为冷硬收束，不再留情面。”

---

## 七、最终回批矩阵草案

这套矩阵只解决一件事：

**这场对话最后怎么收。**

### 1. 输入维度

| 维度 | 建议取值 |
| --- | --- |
| 原始计谋类型 | 试探 / 献策 / 谗言 / 离间 / 设局嫁祸 / 借刀 / 求援 / 谶纬 / 煽动割据 / 煽动造反 |
| 补答质量 | 高 / 中 / 低 |
| 关系温度 | 软 / 摇摆 / 硬 |
| 高压状态 | 低 / 中 / 高 |

### 2. 输出方向

| 输出项 | 说明 |
| --- | --- |
| 情绪收束方向 | 是暂缓、防备、冷记、还是短暂信任 |
| 是否翻旧账 | 是否适合顺手提旧账来加压 |
| 是否给台阶 | 是否让 NPC 保留一条继续来往的缝 |
| 是否加深防备 | 结尾应否更硬 |
| 长度建议 | 偏短 / 正常 / 偏长 |

### 3. 几类典型组合

#### `补答质量高 + 关系软 + 高压低`

- 适合“暂时信你，顺手给一步”
- 结尾可稍放软
- 可以不翻旧账
- 可保留合作缝隙

#### `补答质量中 + 关系摇摆 + 高压中`

- 适合“表面揭过，暗里记账”
- 结尾不应太软
- 可轻提一笔旧账或局势压力
- 给台阶，但不完全松口

#### `补答质量低 + 关系硬 + 高压高`

- 适合“越描越黑，疑心更深”
- 结尾应短、冷、收死
- 可翻旧账
- 不再留新的回话钩子

---

## 八、推荐的生成顺序

为避免追问链路和原始北周 NPC 回应脱节，建议后续 prompt 里的表现顺序仍然遵守北周既有逻辑：

1. 人物声音
2. 计谋反应方向
3. 高压偏移
4. 关系远近与记忆
5. 原始局面透传
6. 追问增量摘要
7. 收束要求

这样做的好处是：

- 玩家会听见“还是这个人”
- 但又能感觉“他听了你的补答之后，态度确实变了”

---

## 九、Fallback 设计要求

如果 DS 调用失败，fallback 也不能只是一句系统兜底话。

最低要求应满足：

1. 保留角色自称和人物气质
2. 仍有明确立场方向
3. 仍像对话收束，而不是系统说明
4. 长度不低于正常输出的大约 60%

同时建议 fallback 也至少区分两类：

- 补答大致稳住
- 补答没有稳住

这样即便 DS 不可用，玩家也不会觉得这条链路突然塌成死模板。

---

## 十、测试建议

### 1. prompt wiring test

确认以下内容真的进入追问最终回批 prompt：

- 原始上下文透传字段
- 四个追问增量字段
- 三条自然语言裁剪摘要

### 2. matrix behavior test

确认不同组合下，最终回批方向真的有差别：

- 高质量补答时更容易出现“暂时信你”
- 低质量补答时更容易出现“越描越黑”
- 高压组合下更短更硬

### 3. continuity test

确认最终回批与原始北周 NPC 回应之间口风连续：

- 仍像同一个人
- 仍处在同一局里
- 不会突然变成另一种叙述视角

### 4. fallback parity test

确认 fallback 仍满足：

- 有自称
- 有立场
- 长度合格

---

## 十一、这份底稿想达到的玩家效果

玩家最终应感到：

- NPC 真在听我补答
- 我的补答不是“额外多打一段字”，而是真能改变这场对话的停点
- 同一个 NPC 的前后两段话，是连起来的

如果这个效果成立，追问系统才算真正从“玩法点子”升级成“沉浸式对话机制”。
