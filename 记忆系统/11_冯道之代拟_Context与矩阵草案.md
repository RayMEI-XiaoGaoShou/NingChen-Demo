# 冯道之代拟 Context 与矩阵草案

日期：2026-04-23  
适用对象：玩家在施计页调用冯道之 AI 军师代拟时，由 DS 生成的代拟文本

---

## 一、这份底稿解决什么问题

冯道之现在已经不是“没上下文”的状态了。  
相反，他已经吃到了很多材料：

- 回合局势
- 战局摘要
- 目标本回合公开表态
- 上回往来
- 关系温度
- 近来得失
- 派系压力
- 长期旧账
- 关系旧账
- 玩家危险等级
- 已解锁暗线

所以他的主要问题不是“知道得不够多”，而是：

**系统还没有先帮他把“这一手最该怎么下”裁出来。**

这会带来一种明显体感：

- 他像一个会润色的帮手
- 还不够像一个替玩家下判断的谋士

因此，这条链路的核心任务不是继续堆背景，而是补出：

- 战略判断
- 切口选择
- 风险边界
- 输出模式

---

## 二、链路定位

这条链路的正式定位建议写成：

> 冯道之代拟不是“替玩家润色一句话”，而是在玩家已知信息范围内，替玩家裁剪最值得下手的一刀。

它的职责是：

1. 帮玩家判断这回合最该打哪一层
2. 帮玩家选择最合适的切口
3. 提醒最危险的红线
4. 按合适的谋士模式代写文本

它**不负责**：

- 告诉玩家系统精确阈值
- 代替玩家看到未解锁暗线
- 直接给出“唯一标准答案”

---

## 三、先明确冯道之的信息边界

这一步必须先定，否则后面很容易被玩家认为“开天眼”。

本底稿建议正式采用：

**路线 A：冯道之比玩家更会判断，但不直接知道系统精确数值。**

### 1. 什么叫“允许知道”

可以知道的，是系统翻译后的模糊谋士判断，例如：

- “此人在御前的庇护已经很薄，再压一两回，恐怕就撑不住。”
- “西线那边如今正缺一个能落到粮道上的借口。”
- “这位眼下更在意体面，不在意多赚一层利。”

### 2. 什么叫“不允许知道”

不应直接喂给他的，是：

- 精确数值
- 精确阈值距离
- 未解锁暗线内容
- 玩家尚未看到的系统底层判断

例如不应写成：

- “皇帝恩宠还剩 0.3”
- “再来一次就能进入处置链”

### 3. 这条边界想达到的效果

玩家会觉得：

- 冯道之比我老练
- 但他不是天外神谕

## 四、当前 Context Schema 与目标 Context Schema

### 1. 当前已有输入

当前 `FengDaozhiDraftContext` 已包含：

| 字段 | 用途 |
| --- | --- |
| `round` | 第几回合 |
| `eventName` / `eventBriefing` | 本回合事件与局势 |
| `campaignSummary` | 战局摘要 |
| `schemeLabel` | 本次计谋标签 |
| `targetNpcName` / `targetNpcTitle` / `targetPersona` | 目标人物基础信息 |
| `currentPublicStatement` | 本回合公开表态 |
| `visibleSecrets` | 玩家当前已知暗线 |
| `previousDealings` | 上回往来 |
| `relationshipTemperature` | 关系温度 |
| `recentCourtFortune` | 最近得失 |
| `factionPressure` | 派系压力 |
| `longTermMemorySummary` | 长期旧账 |
| `relationMemorySummary` | 关系旧账 |
| `relationshipSummary` | 关系概括 |
| `courtSituationSummary` | 朝局概括 |
| `playerDangerStage` | 玩家危险等级 |

### 2. 目标新增层：战略裁剪卡

建议在现有上下文之上，新增四类信息。

#### A. 当前最该打哪层

不是精确数值，而是一条模糊判断。  
可选方向包括：

- 信任
- 暗线
- 皇帝恩宠 / 太后眷顾
- 派系值
- 忠诚 / 军力
- 战役准备

#### B. 当前最佳切口

例如：

- 顺着对方私利
- 顺着公开表态反手一拧
- 顺着最近得失
- 顺着旧账
- 顺着战役窗口

#### C. 当前最该避开的红线

例如：

- 太露骨
- 太像替对手探路
- 太早摊牌
- 太空泛
- 太像在说大话

#### D. 当前输出模式

- 探路
- 顺推
- 借势
- 递刀
- 收口
- 留后手

## 五、六种输出模式定义

这六类模式不应只停留在词面上，必须先定义清楚边界。

| 模式 | 定义 | 典型触发场景 |
| --- | --- | --- |
| 探路 | 代拟重心是摸清对方真正介意什么，语气偏试探、留余地 | 信任不足、暗线不足、目标态度未明时 |
| 顺推 | 代拟重心是顺着对方已有松口往下走，不主动加压 | 目标已有松动、关系温度偏软时 |
| 借势 | 代拟重心是把本回合局势中的一件事挂到对方利益或恐惧上 | 本回合事件或战区变化有现成抓手时 |
| 递刀 | 代拟重心是给出一把可执行的由头，让对方能顺势动手 | 某条链路已接近阈值、需要落子时 |
| 收口 | 代拟重心是巩固已有成果，此回合不再加码 | 已有推进，但当前风险较高时 |
| 留后手 | 代拟重心是留一条退路，不把话说满 | 时机未到、目标摇摆、玩家危险偏高时 |

这六类模式的作用，是让冯道之从“替你写一句”升级成“替你判断该怎么写”。

## 六、冯道之输出矩阵草案

这套矩阵的目标是：

**把“知道很多”变成“判断更准”。**

### 1. 输入维度

| 维度 | 建议取值 |
| --- | --- |
| 计谋类型 | 试探 / 献策 / 谗言 / 离间 / 设局嫁祸 / 借刀 / 求援 / 谶纬 / 煽动割据 / 煽动造反 |
| 目标角色类型 | 朝堂 / 外部军头 / 混合型外部角色 |
| 玩家危险等级 | safe / under_watch / threatened 等 |
| 当前是否处于战役窗口 | 是 / 否 |
| 是否已解锁足够暗线 | 是 / 否 |

### 2. 输出方向

| 输出项 | 说明 |
| --- | --- |
| 输出模式 | 六选一 |
| 语气轻重 | 轻 / 中 / 重 |
| 利益重心 | 利人 / 害国 / 派系 / 战区 / 生存 |
| 明说还是留半步 | 直说 / 半说 / 只点一层 |
| 长度建议 | 偏短 / 正常 / 偏长 |

### 3. 角色类型说明

这里建议继续保留三分法：

- `朝堂角色`
- `外部军头`
- `混合型外部角色`

其中独孤文约属于第三类。  
这类角色不能只按普通军头写，也不能只按纯朝臣写。  
冯道之在给他们代拟时，应更先看：

1. 他们在中枢眼里的政治位置
2. 他们在边线的独立性
3. 再看单纯军需和价码

## 七、建议新增的中间摘要

为了不把系统判断原始分数直接塞给模型，建议先翻译成 4 条自然语言摘要。

### 1. 战略重心摘要

例如：

- “这回合更该打他的信任，不宜急着压结构。”
- “这位眼下在太后那边的遮护已经薄了，可顺势往上再压。”

### 2. 最佳切口摘要

例如：

- “可顺着他刚才的公开表态反手一拧。”
- “这回合最好从他最在意的粮道与退路下手。”

### 3. 红线摘要

例如：

- “此时不可把话说得太满，像替旁人探口风。”
- “这一步若说得太急，反倒像你在替他铺路。”

### 4. 输出模式摘要

例如：

- “这一手宜借势，不宜直压。”
- “这一手宜收口，不宜再加码。”

---

## 八、Fallback 设计要求

冯道之 fallback 不能只是“顺着对方利益写”这一条总规则。

最低要求应满足：

1. 仍像谋士，不像系统说明
2. 仍有明确切口和方向
3. 仍保留模式差异
4. 长度不低于正常输出的大约 60%

建议 fallback 至少区分以下方向：

- 试探型代拟
- 献策型代拟
- 高压型代拟（谗言 / 离间 / 设局嫁祸 / 借刀）
- 外部线代拟（求援 / 割据 / 造反）
- 谶纬型代拟

这样即使 DS 不可用，冯道之也不会突然塌成一句中性建议。

---

## 九、测试建议

### 1. prompt wiring test

确认新增的战略裁剪卡真的进入 prompt：

- 当前最该打哪层
- 最佳切口
- 红线
- 输出模式

### 2. mode behavior test

确认不同模式会让代拟方向明显不同：

- 探路时更留余地
- 递刀时更给由头
- 收口时更克制

### 3. information-boundary test

确认冯道之吃到的是模糊判断，而不是精确阈值。

### 4. fallback parity test

确认 fallback 仍满足：

- 像谋士
- 有方向
- 有切口
- 长度合格

---

## 十、这份底稿想达到的玩家效果

玩家最终应感到：

- 冯道之不是单纯帮我润色
- 他是在替我判断，这回合到底该顺势、借势、递刀，还是先收口

如果这个效果成立，冯道之才会真正成为“AI 军师”，而不是“AI 写手”。
