# 《佞臣》NPC 长期记忆第二层优化设计

日期：2026-04-20  
范围：玩家 -> NPC 的长期旧账召回优化  
状态：设计稿

## 1. 背景

当前项目已经完成了 NPC 长期记忆第一层：

- 系统会在回合结算后抽取关键旧账，写入 `npcMemoryLedger`
- 已落地的记忆类型包括：
  - `favor`
  - `saved_face`
  - `warning`
  - `betrayal`
  - `power_shift`
- NPC 回应 prompt 与冯道之代拟 prompt 都已经能读到这层“长期旧账”

这解决了“NPC 是否有跨回合记忆”的问题，但还没有解决“NPC 会不会在不同计谋场景下，读到最相关的旧账”。

当前痛点是：

- 同一名 NPC 面对 `献策` 和 `谗言` 时，系统读到的旧账差别还不够明显
- 当前长期记忆更像统一摘要，而不是按眼前计谋场景做有针对性的召回
- 玩家体感上会更容易感受到“这个人记得我”，但未必能感受到“这个人记得和这手计谋最相关的那件旧事”

## 2. 设计目标

本轮优化只解决一件事：

> 让 NPC 在不同计谋类型下，优先召回不同类型的长期旧账。

目标效果：

1. `献策 / 试探` 更容易召回“你曾替我遮掩、抬身价、给过台阶”的旧账
2. `谗言 / 离间 / 设局嫁祸` 更容易召回“你曾经敲打过我、试图探底、让我起疑”的旧账
3. `谶纬` 更容易召回与“名分、压力、朝局裂缝”有关的旧账
4. 冯道之代拟也能据此更精准判断该顺着哄、还是顺着拆

## 3. 非目标

本轮不解决：

- NPC 与 NPC 之间的关系记忆
- 新增一大批长期记忆类别
- 长期记忆的 UI 可视化展示
- 重新设计记忆抽取逻辑本身

本轮只优化“已经记下来的旧账，后续如何被更准确地调用”。

## 4. 核心思路

将当前的“统一 top-N 旧账摘要”升级为“按计谋类型做相关性召回后的精选摘要”。

新流程分三步：

1. 给每条长期记忆补更细的标签
2. 按计谋类型计算记忆相关性
3. 只把最相关的 1~2 条旧账送进 prompt

这意味着第二层优化的重点不是“记更多”，而是“拿得更准”。

## 5. 标签体系

在现有 `category / tags / schemeType` 基础上，补强以下语义标签：

- `trust`
- `face`
- `pressure`
- `court`
- `military`
- `grain`
- `legitimacy`
- `external`

使用原则：

- 一个旧账可以挂多个标签
- 标签不要求绝对精细，但必须能支撑“按计谋类型召回”
- 第一版不追求复杂机器学习式评分，只用显式权重即可

示例：

- 你替祖珽遮掩失言：
  - `category = saved_face`
  - `tags = [face, trust, court]`
- 你对尉迟暮连续试探其底牌：
  - `category = warning`
  - `tags = [trust, pressure, military]`
- 你曾用谶纬撬动宇文棣名分裂缝：
  - `category = power_shift`
  - `tags = [legitimacy, pressure, court]`

## 6. 按计谋类型的召回规则

建议首版建立一张简单的“计谋 -> 优先记忆标签/类别”映射表。

### 6.1 试探

优先召回：

- `warning`
- `trust`
- `pressure`

语义目标：

- 让 NPC 记得“你是不是常来探我底”

### 6.2 献策

优先召回：

- `favor`
- `saved_face`
- `trust`
- `face`

语义目标：

- 让 NPC 记得“你是否曾替我说话、给我体面、替我抬轿”

### 6.3 谗言 / 离间

优先召回：

- `warning`
- `betrayal`
- `pressure`
- `court`

语义目标：

- 让 NPC 记得“你以前就擅长挑拨、递刀、放大嫌隙”

### 6.4 设局嫁祸

优先召回：

- `betrayal`
- `warning`
- `face`
- `pressure`

语义目标：

- 让 NPC 记得“你以前就会逼我失言、令我难堪、把我往局里推”

### 6.5 谶纬

优先召回：

- `legitimacy`
- `pressure`
- `court`
- `power_shift`

语义目标：

- 让 NPC 记得“你以前就会在名分、天命、朝局风向上动手脚”

### 6.6 外部军头线

优先召回：

- `external`
- `power_shift`
- `pressure`

语义目标：

- 让 NPC 记得“你是在替我抬价、逼我离心，还是逼我明牌”

## 7. 评分与筛选

建议使用显式加权评分，而不是复杂规则堆叠。

每条记忆的相关性分数由以下组成：

- `importance`
- `recency`
- `categoryMatch`
- `tagMatch`
- `sameSchemeTypeBonus`

建议方向：

- `importance` 是主权重
- `tagMatch` 是第二权重
- `recency` 用于打破同分
- `sameSchemeTypeBonus` 只做轻微加成，避免系统过度机械地“只记同类旧账”

最终输出规则：

- 单次最多选 2 条长期旧账
- 如果没有高相关项，则退回当前的一般摘要策略
- 不为了凑数而塞低质量旧账

## 8. Prompt 接入方式

当前长期记忆已接入：

- NPC 回应 prompt
- 冯道之代拟 prompt

本轮不改接入位置，只改进入 prompt 的内容选择方式。

建议输出结构：

- `longTermMemorySummary`
- `selectedLongTermMemories`

其中：

- `selectedLongTermMemories` 是精挑后的 1~2 条明细
- `longTermMemorySummary` 是一句合并摘要，用于兼容旧 prompt 结构

## 9. 示例

### 示例 A：祖珽 + 献策

旧账：

- 第 3 回合你替祖珽挡过一轮失言风波
- 第 7 回合你又替他递过一封能抬身价的献策
- 第 8 回合你曾试探过他的底线

当第 10 回合再次对祖珽使用 `献策` 时，系统应优先召回前两条，而不是把“试探底线”也摆到最前面。

### 示例 B：尉迟暮 + 离间

旧账：

- 第 4 回合你对他做过一次试探
- 第 6 回合你曾让他在军议上失过体面
- 第 9 回合你对他做过一次带明显挑拨意味的谗言

当第 12 回合你再对尉迟暮使用 `离间` 时，系统应优先召回后两条，而不是平均看待所有旧账。

## 10. 风险与边界

### 10.1 风险

- 如果标签过多但抽取质量不稳，可能出现“看似更聪明，实则更随机”的问题
- 如果同类加权过高，NPC 会显得只会机械重复旧话

### 10.2 控制方式

- 第一版只加少量高价值标签
- 先做显式映射，不做复杂权重学习
- 保留回退策略，避免无相关旧账时 prompt 变空

## 11. 验收标准

1. 同一名 NPC，在不同计谋类型下，被选中的长期旧账明显不同
2. `献策` 场景下更容易召回 `favor / saved_face`
3. `谗言 / 离间 / 设局嫁祸` 场景下更容易召回 `warning / betrayal`
4. `谶纬` 场景下更容易召回 `legitimacy / pressure / court`
5. NPC 回应与冯道之代拟都能吃到这层“精选旧账”
6. 没有高相关旧账时，系统能平稳回退，不造成 prompt 断裂
