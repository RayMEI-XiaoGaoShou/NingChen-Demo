# 《佞臣》NPC-NPC 关系记忆第二支线设计

日期：2026-04-20  
范围：NPC A -> NPC B 的跨回合关系记忆  
状态：设计稿

## 1. 背景

当前项目里，NPC 与 NPC 之间已经有“关系状态”，但还没有“关系记忆”。

也就是说：

- 玩家对 A 使用 `谗言 / 离间 / 设局嫁祸 / 借刀` 并指向 B 时
- 系统会修改 A 与 B 的关系边强度
- 但系统不会稳定记住：
  - “A 是不是之前就已经怀疑 B”
  - “A 是不是已经把 B 视为碍事、可恨、可防、可用”

结果是：

- 关系数值会变
- 但 NPC 的语言层不会自然表现出“我对这个人早有旧账”

这会削弱北周计谋链最关键的一种爽感：

> 玩家不是每回合都在从零开始挑拨，而是在持续加深某条旧裂缝。

## 2. 设计目标

本支线要解决的问题是：

> 让 NPC 会记得“另一个 NPC 以前就值得怀疑/令人厌恶/不符合我利益”，并在后续同类施计中把新信息与旧怀疑叠加起来理解。

目标效果：

1. 玩家连续用同一关系线做文章时，NPC 会显得“越听越信，不是每次都像第一次听”
2. NPC 回应会自然体现“旧疑未消，又添新证”
3. 冯道之代拟也能看出“这条线是不是已经被撬松，可以继续加码”

## 3. 非目标

本轮不解决：

- 所有 NPC 之间的自动关系演化
- 大规模社会网络模拟
- 关系记忆的前端可视化面板
- 完整重做所有计谋的数值公式

本轮只处理：

- 玩家显式围绕“某 NPC 对另一 NPC”的施计所留下的关系旧账

## 4. 核心思路

新增一层独立于 `npcMemoryLedger` 的关系记忆账本，用于记录：

> 某个 NPC 对另一个 NPC 的旧疑、旧怨、旧防、旧依赖。

建议概念结构：

- `holderNpcId`
- `subjectNpcId`
- `stance`
- `importance`
- `summary`
- `sourceRound`
- `tags`

其中：

- `holderNpcId`：谁在记
- `subjectNpcId`：记的是谁
- `stance`：记忆方向

## 5. 关系记忆的基本类型

首版建议只做 4 类：

- `suspicion`：起疑、可防、可查
- `resentment`：不满、厌恶、想压
- `fear`：忌惮、怕其坐大、怕其争权
- `reliance`：暂可借重、可暂时联手

其中首版真正高频用到的，主要还是前三类。

## 6. 哪些计谋会写入关系记忆

### 6.1 谗言

写入：

- A 对 B 的 `suspicion`
- 在特定语义下也可轻度写入 `resentment`

适用表达：

- “此人近来有异心”
- “此人有私下串联之嫌”
- “此人趁局坐大，对你不利”

### 6.2 离间

写入：

- A 对 B 的 `resentment`
- 同时可叠加 `suspicion`

适用表达：

- “你们名义上同列一派，实则他早已把你当垫脚石”
- “你替他担风险，他却在借你上位”

### 6.3 设局嫁祸

写入：

- 视结果而定，更多是让目标本人背锅
- 如果设计成 A 看见 B 失态、失言、失措，也可对 A -> B 写入 `suspicion`

首版建议：

- 只在明确存在第二目标、且结果指向“让 A 认为 B 露出了破绽”时，才写入关系记忆

### 6.4 借刀

写入：

- 强化执行者/听话者对被收网对象的 `resentment` 或 `fear`

但首版不必让 `借刀` 成为主要关系记忆来源，因为它更偏收网结果，而非长期铺垫。

### 6.5 谶纬

当前不作为首版主要关系记忆来源。

原因：

- 谶纬在当前系统中的第一目标仍是“名分裂缝与朝局气候”
- 如果同时把它也做成稳定的 A -> B 关系记忆来源，容易与谗言/离间的边界再次混淆

后续若做“谶纬双层回响”，再考虑接入关系记忆。

## 7. 关系记忆的生成原则

不是每次 A 听到 B 的名字都记一笔，只有以下情况才入账：

1. 本次施计被判为成功或高质量成功
2. 文本语义中确实在推动 A 对 B 的看法改变
3. 本回合确实存在第二目标 B
4. 该条信息不是与既有记忆完全重复的低价值噪音

合并原则：

- 同一 `holderNpcId + subjectNpcId + stance` 可累积强度
- 相近摘要不重复堆新记录，而是提升重要度或刷新最近轮次

## 8. 关系记忆如何被读取

当玩家后续再次对 A 使用与 B 相关的计谋时：

- 系统优先检索 `A -> B` 的关系记忆
- 再决定是否把这条“旧怀疑/旧不满”带进 prompt

读取优先场景：

- `谗言`
- `离间`
- `借刀`
- 带第二目标的 `设局嫁祸`

读取结果应表现为：

- NPC 不再像第一次听说 B 的问题
- 而是表现成“此人旧疑未消，新证又至”

## 9. Prompt 表达方式

建议新增一段关系记忆摘要字段，例如：

- `relatedNpcMemorySummary`
- `selectedRelatedNpcMemories`

内容形式应是短句，而不是原始数据对象。

示例：

- “你上回提及宇文棣借南征自重，本相已记在心里；如今又有新迹象，便更难当作巧合。”
- “本公原已疑令狐律光借后党之名扩自己根脚，今日再听你这番话，愈发觉得他不止是顺水推舟。”

## 10. 与玩家-NPC 长期记忆的区别

这条支线需要与“NPC 长期记忆第二层优化”明确分开：

- 玩家-NPC 长期记忆：
  - 解决“这个 NPC 如何记住你”
  - 核心是 `player -> npc`
- NPC-NPC 关系记忆：
  - 解决“这个 NPC 如何记住另一个 NPC”
  - 核心是 `npc A -> npc B`

两者可以同时进入 prompt，但必须是两段不同摘要，避免语义混淆。

## 11. 示例

### 示例 A：祖珽 -> 宇文棣

- 第 5 回合，你对祖珽谗言宇文棣，说其借南征争功
- 该次成功后，系统写入：
  - `祖珽 -> 宇文棣 -> suspicion`
- 第 8 回合，你再次对祖珽使用与宇文棣相关的离间

理想反馈应是：

- 祖珽不再像第一次听闻
- 而会带着“宇文棣此前就可疑”的底色去理解新信息

### 示例 B：尉迟暮 -> 令狐律光

- 第 6 回合，你让尉迟暮认为令狐律光借后党牵制前线
- 第 10 回合，你再借军粮或军械调度问题挑拨两人

理想反馈应是：

- 尉迟暮会自然表现为“这人果然一直有自己的算盘”

## 12. 风险与控制

### 12.1 风险

- 如果入账阈值太低，关系记忆会迅速膨胀
- 如果谗言/离间都大量重复写入，会让 NPC 语气变得机械

### 12.2 控制方式

- 只记录成功或高质量成功
- 同类关系记忆优先合并，不频繁新增
- 单次 prompt 最多只取 1~2 条相关关系旧账

## 13. 验收标准

1. 当玩家连续围绕同一对 A/B 关系施计时，A 的反馈能体现“旧疑未消”
2. 同一关系线的第二次、第三次操作，不再像第一次从零开始
3. NPC prompt 与冯道之代拟都能读到 `A -> B` 关系旧账
4. 没有相关旧账时，不影响现有反馈链路
5. 关系记忆与玩家-NPC 长期记忆在结构和 prompt 中彼此分离，不互相污染
