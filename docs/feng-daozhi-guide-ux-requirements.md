## 原始需求记录

用户后续计划分为两部分：

1. 文案转化

把当前的首回合引导文案，以及一些计谋介绍的内容，改成用冯道之的口吻介绍。

目标效果示例：

> 公子，这个计谋是……

希望通过“冯道之亲自讲解”的方式增加代入感。

2. UI/UX 设计

整体呈现形式贴近游戏当前美术风格。

首回合引导：

- 当触发首回合引导时，页面先变暗。
- 左下角出现冯道之立绘。
- 后续会基于当前立绘生成多个冯道之人物立绘，使切换时效果更好。
- 人物立绘下方或附近出现当前人物台词。
- 台词区域偏右下角显示。
- 玩家点击鼠标可逐句查看冯道之的引导内容。

每回合锦囊：

- 原先设计在回合首页展示。
- 新设计改为第二节，也就是“朝堂势力 / 地方军头”入口页。
- 冯道之出现在左下角。
- 冯道之介绍当回合注意事项。
- 内容拆分为多句话，玩家点击鼠标切换查看。

用户希望同步推进文案优化与 UI/UX 设计。

## UI/UX 初步设计方向

### 0. 当前版本优先原则

后续 UI/UX 与文案接入必须以当前游戏版本为准。

旧版本里的“回合首页、朝堂观察、施计阶段、女帝问政、计谋回报、天道结算”只能作为历史来源和文案素材索引，不能直接作为新设计的页面边界。

当前版本真实页面与体验结构应按代码现状理解：

- `RoundStart`：回合首页，负责展示当回合简报、国力和地图。
- `CourtView` 总览：朝堂总览入口页，包含“朝堂势力”和“地方军头”两个入口。
- `CourtView` 分屏：进入“朝堂势力”或“地方军头”后，展示对应势力/人物舞台。
- `CourtView` 人物详情：查看人物详情，并在详情内通过嵌入式 `SchemeComposer` 施计。
- `EmpressLetter`：女帝问政/密信页。
- `SchemeFeedback`：计谋回报页。
- `EmpressReply`：女帝回信页。
- `Settlement`：结算页。

文案具体放在哪一页、每页放多少句，等待文案优化完成后再最终决定。

UI/UX 形式可以先设计为可复用承载层：文案一旦确定，只需把台词数组接入对应触发点。

### 1. 通用组件方向

建议新增一个可复用的“冯道之对话引导层”，暂名：

- `FengDaozhiDialogueOverlay`

用途：

- 首回合阶段引导。
- 谶纬首次教学。
- 每回合锦囊。
- 后续可扩展到地方军头玩法提示或特殊机制提示。

核心表现：

- 全屏或当前页面范围遮罩变暗。
- 左下角展示冯道之立绘。
- 右下角展示台词框。
- 每次只显示一句台词。
- 点击鼠标或点“继续”进入下一句。
- 最后一句点击后关闭，并写入对应已读状态。

### 2. 首回合引导方向

当前中心弹窗建议改为角色对话式引导层，但不直接沿用旧版本阶段拆分。

待确认点：

- 在当前版本哪些页面触发首回合引导。
- `scheme_phase` 旧 key 是否保留为内部状态，还是改为更贴近当前嵌入式施计体验的新 key。
- 谶纬教学是否也走同一套冯道之对话层。

### 3. 每回合锦囊方向

锦囊不放在回合首页，改放到 `CourtView` 的总览入口页，也就是“朝堂势力 / 地方军头”入口页。

建议触发位置：

- 玩家从回合首页点击“入朝听政”后进入 `CourtView` 总览页。
- 若本回合锦囊未读，则显示冯道之对话引导层。
- 对话结束后，玩家继续选择“朝堂势力”或“地方军头”入口。

建议内容结构：

- 当回合一句总判断。
- 朝堂势力注意事项。
- 地方军头注意事项。
- 若有谶纬或特殊回合机制，追加一句专门提示。
- 若有被冯道之重点提及的人物，与现有“冯道之锦囊提及”标记保持一致。

其中 `scheme_phase` 不恢复旧路由，而是在当前嵌入式 `SchemeComposer` 第一次打开时触发。这样玩家的首回合学习路径完整，同时贴合当前 UI/UX 重构后的流程。

### Q2. 对话引导层是否强制阻塞当前页面操作？

问题：

首回合引导和每回合锦囊出现时，玩家是否必须先逐句读完，才能继续点击当前页面里的其他按钮？例如在“朝堂势力 / 地方军头”入口页，锦囊出现时，玩家是否还能直接点入口？

推荐答案：

采用“软强制阻塞”：对话层出现时页面变暗，当前页面其他交互暂时不可点；玩家点击任意位置或台词框推进下一句，读完后自动解除遮罩并恢复页面操作。

理由：

- 首回合引导和每回合锦囊是当前设计的核心信息入口，应确保玩家至少看完一遍。
- 对话层只显示短句，点击推进成本低，不会像长弹窗那样打断太久。
- 已读状态记录后，同一引导不再自动弹出，避免重复打扰。
- 后续可以在台词框角落加一个很小的“略过”或“收起”控件，但默认主路径是读完。

用户回答：

同意。

结论：

- 对话引导层采用“软强制阻塞”。
- 引导/锦囊显示时，页面变暗并暂时阻止底层按钮操作。
- 玩家点击任意位置或台词框逐句推进。
- 读完后自动解除遮罩，恢复当前页面操作。
- 同一条已读引导不再自动重复弹出。

### Q3. 每回合锦囊的触发频率如何定？

问题：

每回合锦囊现在计划放在当前版本的 `CourtView` 总览入口页，也就是有“朝堂势力 / 地方军头”两个入口的那一页。它应该每回合第一次进入该页时自动出现一次，还是允许玩家每次回到总览页都看到？另外，玩家读完后是否需要提供一个入口手动重看本回合锦囊？

推荐答案：

每回合第一次进入 `CourtView` 总览入口页时自动出现一次；读完后本回合不再自动出现。页面上保留一个轻量的“冯道之锦囊”重看入口，方便玩家在选择朝堂势力或地方军头前重新打开。

理由：

- 自动出现一次，能保证每回合关键信息被玩家看到。
- 不反复弹出，避免玩家在朝堂/地方/详情之间往返时被打断。
- 手动重看入口能承接“锦囊”作为策略提示的价值，尤其适合文案较短但信息密度高的回合提示。
- 这个入口可复用现有“冯道之锦囊提及”视觉语言，保持系统一致性。

用户回答：

页面上不额外保留独立的“冯道之锦囊”重看入口。当回合锦囊看过后，可以放在右上角功能按钮中可以点开的“玩法指引/玩法说明”里。

代码现状补充：

- 当前右上角功能按钮由 `GameHudTools` 提供。
- `GameHudTools` 中已有“玩法说明”按钮。
- 点击后会通过 `openGameplayGuide('gameplay')` 打开 `GameplayGuide` overlay。

结论：

- 每回合第一次进入 `CourtView` 总览入口页时，自动显示当回合锦囊一次。
- 读完后本回合不再自动弹出。
- 不在总览页额外增加独立重看按钮。
- 当回合锦囊的重看入口并入右上角“玩法说明/玩法指引”overlay。
- `GameplayGuide` overlay 后续需要支持展示“本回合冯道之锦囊”模块，且只在有已读/可回看锦囊时显示。

### Q5. 对话层是否支持“跳过/收起”？

问题：

Q2 已确定对话层是“软强制阻塞”：出现时页面变暗，底层按钮暂时不能点，玩家逐句读完后恢复操作。现在需要确认：对话层是否提供一个明确的“跳过/收起”入口？

推荐答案：

首轮实现先提供一个很克制的“略过”入口，但只放在台词框角落，不作为主按钮。点击后视为已读，关闭本次引导/锦囊，本回合或本节点不再自动弹出。

同时保留主交互为“点击任意位置/台词框逐句推进”。

理由：

- 大多数玩家会按默认路径读完，因为主要视觉和操作都在引导他们逐句看。
- 给熟悉玩法或二周目玩家一个退出口，减少强迫感。
- “略过即视为已读”可以避免玩家反复被同一条引导打断。
- 对每回合锦囊而言，略过后仍可从右上角玩法说明中重看。

可选规则：

- 首回合关键引导可以显示“略过”但文案弱化，例如“稍后再看”或“收起”。
- 每回合锦囊可以显示“略过”，因为它本身会进入玩法说明回看。
- 谶纬首次教学若属于关键机制，可考虑不显示“略过”，或显示但需在玩法说明中保留回看。

### Q6. 冯道之立绘与台词框的屏幕布局如何固定？

问题：

你提出“左下角出现冯道之立绘，右下角显示台词”。需要确认这个布局在不同页面和不同屏幕尺寸下是否保持一致，还是根据页面内容动态调整。

推荐答案：

采用统一固定布局：

- 桌面端：冯道之立绘固定在左下角，台词框固定在右下角，二者形成一条底部叙事层。
- 移动端/窄屏：冯道之立绘缩小并靠左下，台词框占据底部主要宽度，必要时覆盖在立绘右侧或上方，保证文字优先可读。
- 不根据不同页面随意改变方位，只允许通过响应式尺寸调整避让。

视觉原则：

- 立绘不放进卡片，不做普通弹窗。
- 页面背景整体变暗，但仍可看出玩家当前所在页面。
- 台词框应像游戏内对话框，不像网页卡片。
- 台词框内只放当前句、说话人名、推进提示、略过入口；不要塞规则列表。

理由：

- 统一位置能建立“冯道之说话”的稳定认知。
- 左下立绘、右下台词不会遮挡当前版本页面顶部 HUD 和右上工具按钮。
- 文案之后可按句长控制，不需要每个页面单独调布局。

用户回答：

同意。

结论：

- 对话层采用统一固定布局。
- 桌面端：冯道之立绘固定在左下角，台词框固定在右下角。
- 移动端/窄屏：立绘缩小并靠左下，台词框占据底部主要宽度，优先保证文字可读。
- 不按页面随意改变方位，只做响应式尺寸调整。
- 对话层应像游戏内角色对话，不像中心弹窗或网页卡片。
- 台词框内容保持克制：当前句、说话人名、推进提示、略过入口。

### Q7. 台词数据结构是否一开始就支持立绘/情绪切换？

问题：

你提到后续会基于当前冯道之立绘生成多个人物立绘，让切换时效果更好。即使首轮可能只有一张现有立绘，数据结构是否要提前支持每句台词指定立绘状态或情绪？

推荐答案：

一开始就支持，但首轮可以只使用默认值。

建议每句台词的数据结构包含：

```ts
interface FengDaozhiDialogueLine {
    id?: string
```
