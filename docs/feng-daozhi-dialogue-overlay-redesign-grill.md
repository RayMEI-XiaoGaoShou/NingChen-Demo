## 用户反馈原文要点

1. 冯道之半身立绘需要贴牢画面底部。
2. 当前背景遮罩过于不透明；理想情况是黑色暗金半透明遮罩，仍能看见背景内容，且越往下遮罩透明度越高。
3. 右侧首回合引导不应以 CSS 框呈现；文字应自然浮现在背景上。
4. 不需要“跳过”按钮。
5. 用户最初提出“首回合引导”可作为右上角文字出现；Grill 后确认不显示右上角内容。
6. 文字呈现区应向左拉长，占据人物立绘右侧的大部分区域。
7. 用户提供了一张基于回合首页的首回合引导示意图作为视觉参考。

## 从示意图提炼的视觉方向

### 整体层级

浮层不再像弹窗，而像“角色叙事层”覆盖在当前游戏页面之上。底层回合首页仍可辨认，但被压暗、降噪，玩家注意力自然落在冯道之和底部台词。

### 背景遮罩

目标不是纯黑遮挡，而是保留页面环境信息：

- 顶部与中部仍能看见标题、朝堂简报、国力面板、地图等轮廓。
- 整体以黑色为主，叠加暗金/褐金的底部氛围。
- 透明度从上到下逐渐增强，底部最暗，以承托立绘和文字。
- 不应出现独立的实心对话框背景。

### 冯道之立绘

立绘需要成为底部第一视觉锚点：

- 左下角贴牢画面底部。
- 不悬浮、不上移、不被台词框遮挡。
- 人物高度应足够大，约占桌面视口高度的三分之一到二分之一。
- 后续立绘变体应能复用同一锚点与尺寸规则。

### 文本呈现

文字不放入卡片或盒子，而是自然浮在遮罩层上：

- 冯道之姓名在文本区左侧上方，使用金色强调。
- 姓名后接一条细金线，形成古风引导条。
- 台词位于姓名下方，横向展开。
- 文本区从立绘右侧开始，向右延展，占据底部大部分宽度。
- “点击继续”在台词下方居中或略偏右，以金色提示。
- 移除“跳过”按钮。

### 段落标签

新浮层不显示右上角段落标签：

- 不在右上角显示“首回合引导”“朝堂势力”“地方军头”“谶纬引导”等 UI 文本。
- 段落类型如需提示，优先通过冯道之台词自然表达。
- 视觉重点保留在贴底立绘、姓名金线、台词正文和“点击继续 >”提示上。

## 当前实现差异

- 使用 `feng-daozhi-dialogue-box` 渲染有边框、有背景、有阴影的对话框。

- 底部存在“点击继续”和“跳过”按钮。

- 移动端为了避免遮挡曾让立绘上移，但这与新反馈“贴牢画面底部”相反，后续应按新设计重调移动端方案。

## Grill Me 问题与回答

### Q1：这套视觉规范应用范围是什么？

问题：这套“无框浮字 + 贴底立绘 + 暗金渐变遮罩”的视觉规范，是只用于回合首页首回合引导，还是也用于朝堂入口页的每回合锦囊、谶纬引导等所有冯道之对话？

推荐答案：统一用于所有冯道之引导/锦囊，包括首回合引导、每回合锦囊、谶纬引导。原因是冯道之本身是一个角色叙事层，统一视觉会比“首回合一种、锦囊一种”更稳定，后续立绘变体与文案优化也更容易复用。

用户回答：同意。该视觉规范统一用于所有冯道之引导/锦囊，包括首回合引导、每回合锦囊、谶纬引导等。

结论：冯道之浮层后续应作为统一的角色叙事层设计，而不是首回合专属样式。所有场景复用同一套遮罩、贴底立绘、无框浮字、姓名金线与点击推进交互。

### Q2：是否所有冯道之浮层都移除可见“跳过”按钮？

问题：用户明确指出首回合引导不需要“跳过”按钮。既然 Q1 已确认视觉规范统一用于所有冯道之对话，那么“跳过”按钮是否也应在所有冯道之浮层中移除？

推荐答案：所有冯道之浮层都移除可见“跳过”按钮。原因是新设计要从“弹窗操作”转为“角色台词浮层”，可见跳过按钮会把画面重新拉回网页弹窗感。交互上保留点击任意区域、Enter、Space 推进即可；是否保留 Esc 作为隐藏的快捷关闭，需要另行确认。

用户回答：同意。所有冯道之浮层都移除可见“跳过”按钮。

结论：新浮层不再提供可见跳过按钮，避免破坏“无框浮字”的角色叙事感。基础推进交互保留点击、Enter、Space。是否保留 Esc 快捷关闭在后续问题单独确认。

### Q3：“点击继续”提示是否保留，以及放在哪里？

问题：示意图中保留了“点击继续 >”提示。新浮层移除“跳过”后，是否保留该提示？如果保留，它应当在台词下方居中、略偏右，还是直接跟在正文末尾？

推荐答案：保留可见“点击继续 >”，位置采用示意图风格，放在台词区下方中线略偏右，不跟正文混排。原因是移除跳过按钮后，玩家仍需要一个轻量交互提示；把它作为金色小字放在下方，比按钮更符合古风叙事层，也不会干扰正文阅读。

用户回答：保留，放在台词区下方居中，采用示意图那种金色小字，且需要“一闪一闪”的动态提示。

结论：新浮层保留“点击继续 >”提示，但它不是按钮。位置固定在台词正文下方居中，颜色为暗金/亮金小字，并加入轻量闪烁或呼吸动画，提示玩家可点击推进。

### Q4：“点击继续”的闪烁动效应采用哪种强度？

问题：用户希望“点击继续”一闪一闪。这里需要确认闪烁强度：是明显的明灭闪烁，还是更克制的金色呼吸/微亮脉冲？

推荐答案：采用克制的金色呼吸/微亮脉冲，而不是高频明灭闪烁。原因是冯道之浮层整体偏沉稳古风，呼吸式闪烁能提示玩家点击，又不会抢正文和立绘的注意力；同时应尊重 `prefers-reduced-motion`，在减少动态模式下关闭闪烁，仅保留静态金色提示。

用户回答：同意。采用克制的金色呼吸/微亮脉冲，并在减少动态模式下关闭动画。

结论：“点击继续 >”使用低频、低幅度的金色呼吸动效。动效目标是提示可点击，不制造网页广告式闪烁。实现时需要加入 `prefers-reduced-motion: reduce` 兜底，减少动态时提示保持静态。

### Q5：右上角段落标签如何显示？

问题：用户提出右上角显示“首回合引导”文字。统一视觉规范后，该位置是否应固定用于显示当前对话段落标签，例如“首回合引导”“朝堂势力”“地方军头”“谶纬引导”？

推荐答案：右上角固定显示当前段落标签，首回合显示“首回合引导”，锦囊按当前 sequence/line 显示“朝堂势力”或“地方军头”，谶纬显示“谶纬引导”。该标签不是按钮，不加边框，不进入台词区，只作为轻量状态文字贴在右上角功能区附近。

用户回答：不同意。用户觉得不需要显示右上角内容。

结论：新冯道之浮层不显示右上角段落标签。当前段落信息不再以右上角文字呈现；视觉重点保留在冯道之立绘、姓名金线、台词正文与“点击继续 >”提示上。若后续需要区分“首回合引导 / 朝堂势力 / 地方军头 / 谶纬引导”，优先通过文案第一句自然说明，而不是增加 UI 标签。

### Q6：遮罩透明度应让底层内容可读，还是只保留轮廓？

问题：用户希望背景是黑色暗金半透明遮罩，能看到背景内容，且越往下遮罩透明度越高。这里需要确认底层内容的可见程度：是仍可阅读朝堂简报与数值，还是只要能辨认页面结构和地图轮廓即可？

推荐答案：底层内容保持“可辨认结构、局部可读，但不鼓励阅读”。顶部和中部透明度较高，让玩家知道自己仍在原页面；底部遮罩更厚，用于承托冯道之和台词。不要让底层朝堂简报抢过台词正文，也不要把背景压成纯黑。

用户回答：同意。遮罩目标为“可辨认结构、局部可读，但不鼓励阅读”。

结论：遮罩采用黑色暗金半透明渐变。顶部/中部保留底层页面结构和局部文字可读性，底部加厚、加暗、带暗金氛围，用于承托立绘和台词。实现时避免纯黑不透明，也避免背景内容亮度过高而抢走台词注意力。

### Q7：桌面端冯道之立绘尺寸应采用哪种基准？

问题：用户希望冯道之半身立绘贴牢画面底部。示意图中立绘偏克制，约占画面高度三分之一到五分之二。实现时应更接近示意图的小半身，还是略微放大以突出角色存在感？

推荐答案：桌面端采用“略大于示意图但不过分压画面”的中等半身：贴底，左侧锚定，人物高度约为视口高度的 42%-50%，宽度约为 16%-22% 视口宽度；在 16:9 桌面下露出完整上半身和手中竹简，头部位于底部台词区上方，台词从人物右侧开始，不压住人物主体。

用户回答：同意。桌面端采用略大于示意图、但不过分压画面的中等半身。

结论：桌面端冯道之立绘贴牢底部、左侧锚定，人物高度约为视口高度的 42%-50%，宽度约为 16%-22% 视口宽度。16:9 桌面下应露出完整上半身和手中竹简，台词从人物右侧开始，不覆盖人物主体。

### Q8：移动端是否也坚持“立绘贴底 + 无框浮字”？

问题：桌面端已确定立绘贴底、文字横向铺在人物右侧。但移动端宽度有限，如果也强行让文字在人物右侧横向铺开，可能导致台词太窄、换行过多。移动端应如何处理？

推荐答案：移动端仍保持“立绘贴底”和“无框浮字”，但允许布局变为上下层：冯道之贴左下底部，人物尺寸降低；台词区覆盖在底部偏右/中下方，使用更强的底部暗金遮罩保证可读。若宽度不足，台词可跨过人物右侧延伸到全宽，但不得出现实体对话框，也不得把人物脸部完全压住。

用户回答：同意。移动端仍可沿用该方向，但当前版本不用太考虑移动端体验。

结论：移动端不是本次重构重点。实现时只需保证基本可用、不出现严重遮挡或完全不可读；主要设计和验收以桌面端为准。若移动端空间不足，可以采用简化适配：立绘仍贴底但缩小，台词区保持无框浮字，底部遮罩加厚保证可读即可。

### Q9：键盘交互如何保留？

问题：可见“跳过”按钮已确认移除。当前实现支持点击、Enter、Space 推进。新设计中是否继续保留这些键盘推进方式？另外，是否需要 Esc 作为隐藏快捷关闭/跳过整段？

推荐答案：保留点击任意区域、Enter、Space 推进；不启用 Esc 跳过。原因是可见跳过按钮已经移除，若 Esc 仍可直接关闭，容易造成误触漏看关键新手引导。锦囊/引导都应以逐句点击为主。若后续用户强烈需要快速略过，可再设计一个不破坏画面的长按或设置项，而不是先放 Esc。

用户回答：同意。保留点击任意区域、Enter、Space 推进；不启用 Esc 跳过。

结论：新浮层主要交互为逐句推进。玩家可以点击任意浮层区域，也可以使用 Enter 或 Space。移除可见跳过按钮后，不额外提供 Esc 关闭/跳过，避免误触导致漏看关键引导。

### Q10：每回合锦囊是否必须逐句看完？

问题：每回合锦囊可能包含“朝堂势力”和“地方军头”两段，句数比首回合单段更多。移除跳过按钮后，是否允许玩家一键略过长队列，还是所有冯道之内容都必须逐句点击看完？

推荐答案：当前版本统一逐句看完，不提供一键略过。理由是每回合锦囊本身就是本设计的核心玩法提示，且用户已经要求玩法说明里只保留摘要、不做“重听锦囊”。为了避免玩家误跳过后无法重看完整台词，当前先让首次出现的锦囊必须逐句确认。后续如果测试发现节奏过慢，可再通过“缩短句数/优化文案”解决，而不是加跳过。

用户回答：同意。每回合锦囊也统一逐句看完，不提供一键略过。

结论：所有冯道之浮层首次出现时都必须逐句推进完毕，当前版本不提供跳过整段/整队列能力。若后续节奏偏慢，优先通过减少单次句数、压缩文案、优化句子节奏处理，而不是恢复跳过按钮。

### Q11：桌面端文字区横向范围和行长如何定？

问题：用户希望文字呈现区向左拉长，占据人物立绘右侧大部分区域。需要确认桌面端的文字区起点、终点与行长控制，避免文字太短像弹窗，也避免单行太长导致阅读疲劳。

推荐答案：桌面端文字区从冯道之立绘右侧约 24-40px 处开始，向右延展到屏幕右侧安全边距前，整体占据底部可用宽度的约 65%-75%。正文不放入实体框，使用 `max-width` 控制为约 900-1080px；16:9 桌面下一句可自然排成 1-2 行，单行视觉长度约 34-44 个汉字。这样符合示意图的横向叙事感，也不会变成满屏长行。

用户回答：同意。文字区按该横向范围和行长控制。

结论：桌面端台词区从冯道之立绘右侧 24-40px 处开始，向右延展至屏幕右侧安全边距前，占据底部可用宽度约 65%-75%。正文无实体框，最大宽度约 900-1080px；16:9 桌面下一句通常为 1-2 行，单行约 34-44 个汉字。

### Q12：姓名金线是否按示意图保留？

问题：示意图中“冯道之”姓名后有一条细金线，并带小装饰节点，形成文字区的视觉锚点。新浮层是否应保留这一样式？

推荐答案：保留“冯道之 + 细金线 + 小装饰节点”的样式，作为台词区唯一的轻装饰。姓名使用更亮的金色与书写感字体，细金线向右延伸但不贯穿全屏，节点或小纹样保持低调。这样既能替代原 CSS 对话框的边界感，又不破坏“无框浮字”目标。

用户回答：同意。保留“冯道之 + 细金线 + 小装饰节点”的轻装饰样式。

结论：台词区顶部保留姓名金线。它是无框浮字层的主要视觉锚点，用来替代原对话框边界。姓名更亮，金线和节点低调，不贯穿全屏，不做厚重边框。

### Q13：单句字数与每段句数如何控制？

问题：新浮层无实体框，文字横向铺开。为了避免台词过长压住画面或造成阅读疲劳，需要定义文案分句原则。首回合引导、谶纬引导、每回合锦囊的单句字数和总句数应如何控制？

推荐答案：单句建议 28-46 个汉字，最长不超过 60 个汉字；每个 sequence 建议 2-5 句。每回合锦囊的“朝堂势力”和“地方军头”可各自作为独立 sequence/section，单段不超过 4 句；若信息多，优先压缩为关键人物和一条行动建议，不在浮层里展开长解释。文案优化时以“冯道之一句一句点拨”为目标，而不是说明书段落。

用户回答：这条线暂时不用管。用户正在同步优化首回合引导和冯道之锦囊文案，后续文案优化完成后，再考虑单句字数、行长和句数约束。

结论：暂不在本轮锁定文案分句与字数上限。当前 UI/UX 需求只要求文本区有足够横向空间，能承接后续优化后的文案；最终行长、句数和拆句规则待文案定稿后再回看。

### Q14：本轮实现范围是否只改 UI 载体，不改文案机制？

问题：用户正在并行优化文案，因此本轮 UI/UX 实现是否应只重构冯道之浮层的视觉与交互载体，不主动改首回合引导、谶纬引导、每回合锦囊的具体文案和队列机制？

## 最终需求摘要

### 范围

本轮只重构冯道之浮层 UI 载体，不改文案机制、不改首回合引导/谶纬引导/每回合锦囊的队列逻辑，也不主动改具体台词内容。后续文案优化完成后，再按最终文案回看分句、行长和句数。

### 视觉要求

1. 所有冯道之引导/锦囊统一使用新浮层，包括首回合引导、谶纬引导、每回合锦囊。
2. 浮层是角色叙事层，不是弹窗；不再出现实体 CSS 对话框、边框、卡片背景。
3. 背景为黑色暗金半透明渐变，顶部/中部保留底层页面结构和局部可读性，底部更暗更厚以承托立绘和台词。
4. 冯道之立绘贴牢画面左下底部，桌面端高度约为视口 42%-50%，宽度约为视口 16%-22%。
5. 台词区从立绘右侧 24-40px 处开始，向右延展至屏幕右侧安全边距前，占据底部可用宽度约 65%-75%，正文最大宽度约 900-1080px。
6. 台词区保留“冯道之 + 细金线 + 小装饰节点”作为唯一轻装饰。
7. 不显示右上角段落标签。
8. 移动端不是本轮重点，只需基本可用、不严重遮挡或不可读。

### 交互要求

1. 移除所有可见“跳过”按钮。
2. 所有冯道之浮层首次出现时都逐句推进完毕，不提供一键略过整段/整队列。
3. 保留点击任意浮层区域、Enter、Space 推进。
4. 不启用 Esc 跳过或关闭。
5. 保留底部居中的“点击继续 >”金色小字提示。
6. “点击继续 >”使用克制的金色呼吸/微亮脉冲；在 `prefers-reduced-motion: reduce` 下关闭动画，静态显示。

### 验收要求

1. 自动化测试应锁定：无可见跳过按钮、无实体对话框主视觉、点击/Enter/Space 推进保留、减少动态模式下关闭呼吸动画、所有冯道之 sequence 统一走新浮层。
2. 浏览器截图至少覆盖：桌面 16:9 回合首页首回合引导、桌面 16:9 朝堂入口锦囊、窄屏基础可用。
3. 截图验收重点：半透明遮罩能看见背景结构；立绘贴底；文本无框浮现；文字区横向铺开；“点击继续 >”位于台词区下方居中并有轻微呼吸感。
