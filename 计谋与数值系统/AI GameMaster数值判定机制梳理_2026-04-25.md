# 《佞臣》AI GameMaster 数值判定机制梳理

整理日期：2026-04-25

适用范围：当前本地最新版。本文只梳理机制，不修改代码。

本文面向后续第三方 Agent 审阅，重点解释三条会调用 DeepSeek 的“数值判定链路”：

1. 北周计谋：玩家对北周 NPC 施计后，AI 如何把自然语言转成结构化评分，再由固定公式落到信任、关系、派系、国力等数值。
2. 二次追问回答：NPC 追问一次后，玩家补充回答如何反作用到原计谋的成功率与效果。
3. 女帝问政回答：玩家在南陈问政页写附言后，AI 如何影响南陈五维、问政余波与战役推进。

核心结论：当前 AI GameMaster 已经不是“自由裁判”，而是“受限裁判”。DeepSeek 主要负责把玩家文本解析成一组有限字段，所有字段都会被 clamp 到指定范围；真正的成功率、倍率、数值变动、早期压缩、战役推进、失败惩罚，都由本地固定公式决定。AI 可以影响走向和强弱，但不能直接写入最终数值。

---

## 1. 总体架构：AI 只做结构化判定，公式负责落数值

当前三条链路都遵循同一套设计：

| 环节 | 作用 | 是否由 AI 决定 | 收束方式 |
|---|---|---:|---|
| 玩家输入 | 计谋说辞、追问回复、女帝附言 | 玩家决定 | UI 和计谋类型限定 |
| Prompt 构造 | 把当前回合、人物、计谋、历史记忆、玩家文本交给 AI | 本地代码决定 | 只给必要上下文 |
| JSON 解析 | AI 输出结构化评分 | AI 决定 | 只能输出预设字段 |
| JSON 清洗与重试 | 去代码块、解析 JSON、必要时重试 | 本地代码决定 | 失败返回 null |
| Normalize / Clamp | 把字段限制在合法范围 | 本地代码决定 | 0-1、-1 到 1、小范围 delta |
| Fallback | AI 不可用或 JSON 无效时走关键词启发式 | 本地代码决定 | 不阻断游戏 |
| 成功率与倍率 | 根据信任、难度、计谋类型、AI 评分算成功率 | 本地公式决定 | clamp 0.05-0.98 等 |
| 数值模板 | 不同计谋成功/失败触发不同人际、派系、国力模板 | 本地公式决定 | 预设模板 |
| 最终落数值 | 改 NPC、派系、国力、战役动量、问政余波 | 本地公式决定 | 数值上下限与早期压缩 |

这个架构的目的：让 AI 负责理解“这段话到底像不像一个有效计谋”，但不允许 AI 自由决定“北周国力扣多少”。

## 2. AI 服务层：JSON 输出、二次解析重试与 fallback

### 2.1 当前模型配置

当前 DeepSeek 配置已经从旧的 Kimi 命名迁移到 DeepSeek 命名：

| 配置项 | 当前含义 |
|---|---|
| `VITE_DEEPSEEK_API_KEY` | DeepSeek API Key |
| `VITE_DEEPSEEK_BASE_URL` | 默认 `https://api.deepseek.com` |
| `VITE_DEEPSEEK_MODEL` | 当前默认 `deepseek-v4-flash` |
| 兼容项 | 旧的 `VITE_KIMI_*` 仍可兼容读取，但不再建议作为主命名 |

如果模型名以 `deepseek-v4` 开头，请求体会显式加入 `thinking: { type: 'disabled' }`，也就是使用 V4 Flash 的非思考模式。当前结构化裁判字段较窄、公式收束较强，非思考模式一般足够；如果未来要让 AI 判断更复杂的多目标因果链，可以考虑为“解析链路”单独切到更强模型或开启思考模式。

### 2.2 JSON 调用机制

所有结构化判定都通过 `chatCompletionJson<T>`：

1. 调用普通 chat completion。
2. 清理返回文本中的 ```json 代码块。
3. 尝试 `JSON.parse`。
4. 如果第一次失败，并且文本看起来像“被截断的 JSON”，会用更高 `maxTokens` 重试一次。
5. 如果仍失败，返回 `null`。
6. 调用方收到 `null` 后进入本地 fallback 逻辑。

重试不是无条件重试。只有返回内容像 JSON 开头但结尾不完整时才会重试，例如 `{...` 或 `[...]` 被截断。若模型返回解释性文字、散文、空文本，则直接 fallback。

### 2.3 当前 JSON 防线

当前防线有四层：

| 防线 | 说明 |
|---|---|
| System prompt | 要求只输出 JSON，不得输出解释、代码块或多余文字 |
| JSON parse | 非 JSON 直接失败 |
| normalize | 缺失字段补默认值，枚举非法时回落中性值 |
| clamp | 所有数字限制到合法范围 |

一个重要自审点：北周计谋与女帝问政复用的结构化 system prompt 写着“所有数值字段必须落在 0 到 1 之间”，但北周计谋里存在 `stateBenefit`、`targetBenefit`、`factionBenefit`、`legitimacyDirection` 等 -1 到 1 的 signed 字段。代码层 clamp 是正确的，但 system prompt 表述可能会让模型不愿输出负数。建议后续改为“除特别标注字段外，所有数值字段必须落在 0 到 1 之间；signed 字段按字段说明输出 -1 到 1”。

## 3. 北周计谋 AI 判定链路

### 3.1 输入给 AI 的上下文

北周计谋解析 prompt 会向 AI 提供以下信息：

| 上下文 | 用途 |
|---|---|
| 当前回合与事件 | 判断说辞是否贴合当回合局势 |
| 事件简报 | 判断玩家是否抓住当前朝局焦点 |
| 施计对象类型 | 朝堂人物或地方军头 |
| NPC 姓名、官职、公开人设、公开立场 | 判断是否符合人物利益和说话对象 |
| NPC 性格、软肋、触发点 | 判断 characterFit 与风险 |
| 计谋类型 | 决定不同判定标准 |
| 玩家说辞 | 核心自然语言输入 |
| 谶纬专用的谶辞与解释 | 谶纬分成“征兆文本”和“解释文本” |
| 关联人物 | 谗言、离间、借刀等需要第二对象 |

AI 不会直接看到全部隐藏真相，而是基于当前可用上下文、公开设定、已解锁信息和当前回合态势来判断。

### 3.2 北周计谋 JSON Schema

北周计谋解析会输出 `NorthSchemeParseResult`。可以理解为“这条计谋文本的结构化画像”：

| 字段 | 范围 | 含义 |
|---|---:|---|
| `characterFit` | 0-1 | 是否贴合施计对象的性格、利益、软肋 |
| `eventFit` | 0-1 | 是否贴合当回合朝局事件 |
| `structuralPenetration` | 0-1 | 是否能穿透到权力链、粮道、军令、派系、国力层 |
| `executability` | 0-1 | 计谋是否可执行，不只是空泛挑拨 |
| `exposureRisk` | 0-1 | 玩家意图暴露、引火烧身的风险 |
| `financeRelevance` | 0-1 | 与财政的相关度 |
| `grainRelevance` | 0-1 | 与粮赋、粮道、仓廪的相关度 |
| `militaryRelevance` | 0-1 | 与军力、兵权、军需的相关度 |
| `socialOrderRelevance` | 0-1 | 与社会秩序、民心、流民、叛乱的相关度 |
| `governanceRelevance` | 0-1 | 与治理穿透力、中枢调度、官僚执行的相关度 |
| `dominantIntent` | 枚举 | 主要意图：诱导、分化、取信、试探、煽动、伤国、中性等 |
| `stateBenefit` | -1 到 1 | 对北周整体是否有利，正数有利，负数伤国 |
| `targetBenefit` | -1 到 1 | 对施计对象个人是否有利 |
| `factionBenefit` | -1 到 1 | 对施计对象所属派系是否有利 |
| `advicePolarity` | 枚举 | 献策是利国、利己伤国，还是模糊 |
| `legitimacyDirection` | -1 到 1 | 对名分、法统、天命合法性的方向 |
| `omenPolarity` | 枚举 | 谶纬是巩固合法性、破坏合法性，还是空泛 |
| `selfTrapPotential` | 0-1 | 设局嫁祸是否能让目标自己露破绽 |
| `scapegoatClarity` | 0-1 | 嫌疑是否明确回落到目标身上 |
| `omenAnchorStrength` | 0-1 | 谶辞是否像灾异、征兆、谶语，而不是普通政论 |
| `legitimacyCrack` | 0-1 | 谶纬是否击中了名分裂缝 |
| `suspicionDirection` | 0-1 | 谶纬是否明确把疑心指向某对象 |
| `suspicionTransmission` | 0-1 | 谗言是否能从私人怀疑传导到权力/军令/粮道层 |
| `fractureTransmission` | 0-1 | 离间是否能让合作关系出现真实裂缝 |
| `proxyTransmission` | 0-1 | 借刀是否能从怀疑传导到罢黜/处决链 |
| `evidence` | 字符串数组 | AI 给出的不超过 3 条判定依据 |

枚举字段如果输出非法值，会被归为中性。数字字段若缺失或非法，会补默认值并 clamp。

### 3.3 各计谋的 AI 判定重点

| 计谋 | AI 主要看什么 | 设计目的 |
|---|---|---|
| 试探 | 是否贴合人物、是否能探口风、是否风险可控 | 主要解锁暗线和轻微信任变化，不应直接重伤国力 |
| 献策 | 是否“对目标个人有利，但对北周整体不利” | 防止玩家写纯粹利国政策也被判成伤北周 |
| 谗言 | 是否让 A 对 B 起疑，且疑心能传导到军令、粮道、权力链 | 降低 B 的皇帝恩宠或太后眷顾，或伤派系 |
| 离间 | 是否让既有合作关系出现裂缝，不只是泛泛说坏话 | 更强地破坏关系、派系稳定、协同能力 |
| 设局嫁祸 | 是否让目标自己失言、失态、失措，并让嫌疑回到目标身上 | 不是“说服目标”，而是“让目标掉进局里” |
| 借刀 | 是否具备执行者、被处置者、处置理由、上达链条 | 触发罢黜/处决链，而不是任意角色杀任意角色 |
| 谶纬 | 是否有玄学征兆，是否解释名分裂缝，是否指向可疑对象 | 特色玩法，不依赖信任，更强调灾异、天命、合法性 |
| 煽动割据 | 是否能推动地方军头脱离中枢、割据一方 | 依赖地方军头忠诚度、信任、暗线等硬条件 |
| 煽动造反 | 是否能推动地方军头起兵，并承担平叛风险 | 比割据更高风险、更高国力冲击 |

### 3.4 AI 解析后的 normalize 与 fallback

北周计谋解析完成后会进入 normalize：

1. 所有 0-1 字段被限制在 0 到 1，并保留两位小数。
2. signed 字段被限制在 -1 到 1，并保留两位小数。
3. `evidence` 只保留非空字符串，最多 3 条。
4. 枚举字段不合法时回落到中性。
5. 若 AI 返回的五维相关度全部为 0，会从本地关键词 fallback 中补五维相关度，避免 AI 过度漏判。
6. 谶纬字段如果 AI 漏填，会合并本地 fallback 的灾异、名分、疑心指向等字段。

如果 AI 调用失败或 JSON 无效，则走 `fallbackNorthParseFromSpeech`。fallback 是关键词启发式，主要根据：

| fallback 维度 | 判断方式 |
|---|---|
| 人物贴合 | 是否命中 NPC 软肋、公开立场、暗线、公开人设 |
| 事件贴合 | 是否命中回合事件标题、简报、北周状态关键词 |
| 结构穿透 | 是否出现军令、粮道、中枢、派系、御史、太后、皇帝等结构词 |
| 可执行性 | 是否包含上奏、收紧、削饷、调兵、借名义等行动词 |
| 暴露风险 | 是否直白、越界、威胁味过重 |
| 五维相关度 | 根据财政、粮道、军力、民生、治理关键词判断 |
| 献策方向 | 识别利国、利目标伤国、模糊 |
| 谶纬方向 | 识别灾异、天命、名分裂缝、疑心指向 |

自审：fallback 保证了离线可玩，但它比 AI 更容易被关键词堆砌利用。因此它适合作为断网兜底，不适合作为长期高精度裁判。

### 3.5 成功率计算：AI 评分只是一部分

计谋是否成功并不是 AI 直接决定，而是：

```text
最终成功率 =
  计谋基础成功率
  + 信任加成
  + 计谋类型修正
  + 难度修正
  + characterFit / executability / eventFit 加成
  - exposureRisk 惩罚
  + 二次追问成功率 delta
  - 同一 NPC 同回合重复施计惩罚

最后 clamp 到 0.05 - 0.98
```

其中：

| 项 | 来源 | 说明 |
|---|---|---|
| 基础成功率 | 难度档配置 | 简单更高，困难/地狱更低 |
| 信任加成 | NPC 对玩家信任 | 达到解锁阈值后额外加成 |
| 计谋类型修正 | 固定表 | 借刀、谶纬、煽动造反等天然更难 |
| AI 解析加成 | JSON 字段 | 人物贴合、执行性、事件贴合提高成功率 |
| 暴露风险 | JSON 字段 | 越露骨越降低成功率 |
| 二次追问 | follow-up JSON | 小幅修正原计谋，不重算成第四计 |

谶纬是例外。谶纬成功率不吃信任加成，而是使用专门公式：

```text
谶纬成功率 =
  难度基础值
  + 谶纬基础补正
  + omenAnchorStrength
  + legitimacyCrack
  + suspicionDirection
  + eventFit
  + structuralPenetration
  - exposureRisk
  - 同 NPC 重复惩罚

最后 clamp 到 0.14 - 0.94
```

这样做符合当前设计：谶纬是公共神秘主义/舆论/天命工具，不应主要取决于被施计对象对玩家的信任。

### 3.6 成功后如何落数值

计谋成功后先生成模板，再乘以倍率：

```text
人物倍率 =
  0.9
  + characterFit * 0.85
  + executability * 0.35
  再乘二次追问效果倍率
  clamp 0.8 - 2.1

派系倍率 =
  0.85
  + eventFit * 0.55
  + structuralPenetration * 1.0
  再乘二次追问效果倍率
  clamp 0.75 - 2.4

国力倍率 =
  若 structuralPenetration >= 0.45：
    0.68 + structuralPenetration * 0.9 + eventFit * 0.2
  否则成功也只给 0.5
  再乘早期回合压缩与二次追问倍率
```

早期回合有额外国力压缩：

| 回合 | 常规计谋国力倍率 |
|---:|---:|
| 1-6 | 0.42 |
| 7-12 | 0.72 |
| 13-20 | 1.00 |

这能避免前几回合玩家尚未理解系统时，普通计谋过早打穿北周国力。

### 3.7 各计谋主要数值模板

以下是“理想成功路径”的简化说明。实际数值还会受 AI 评分、难度、早期压缩、五维相关度、NPC 类型、关联对象影响。

| 计谋 | 主要人物层效果 | 主要派系/国力层效果 |
|---|---|---|
| 试探 | 目标信任小幅上升，解锁暗线 | 通常不直接伤国 |
| 献策 | 目标信任上升；地方军头可能忠诚下降或军力变化 | 若是利目标伤国，会损北周财政、粮赋、治理、秩序等相关维度；若是利国献策，可能反而帮北周 |
| 谗言 | 目标信任小幅变化，关联人物信任或恩宠下降 | 若疑心传导到军令/粮道/派系，会损派系稳定与国力 |
| 离间 | 关联人物关系受损更重 | 比谗言更强地伤内部稳定、朝堂影响或军事实力 |
| 设局嫁祸 | 目标信任变化；目标皇帝恩宠/太后眷顾可能下降 | 若目标自陷明确，会伤治理、秩序、派系声望；对地方军头可解释为中枢收紧军需 |
| 借刀 | 对已满足阈值的朝堂目标触发罢黜/处决链 | 关键人物被罢黜/处决会造成显著国力损伤 |
| 谶纬 | 朝堂目标：恩宠/眷顾、名分与派系压力变化；地方军头：忠诚明显下降、军力小幅下降 | 对朝堂可伤合法性、治理、秩序；对地方军头表现为中枢疑心导致削饷、监军、军需收紧 |
| 煽动割据 | 地方军头进入割据状态 | 北周五维明显受损，但低于造反 |
| 煽动造反 | 地方军头起兵，可能被平叛 | 若成功，国力冲击更高；若被平叛，仍可能消耗北周但目标状态不同 |

### 3.8 国力五维如何被收束

计谋不会直接让 AI 输出“财政 -3”。实际流程如下：

1. 计谋模板产生人物变化、派系变化、特殊行动。
2. 派系变化汇入国力，例如内部稳定下降会影响社会秩序、治理穿透力等。
3. 地方军头忠诚或军力变化汇入国力，例如边镇军力下降影响北周军事和粮道。
4. 献策方向、谶纬方向、战略外溢进一步修正五维。
5. 对谗言/离间/借刀存在 transmission gate：如果 AI 判断只是私人坏话，无法传导到权力链，国力影响会被压低或清零。
6. 统一乘以国力倍率、早期压缩、低风险 damping。
7. 最后落入北周五维，并由国家维度 clamp 限制在合法范围。

这套链路是当前“可解释性”的核心：玩家一句话要想影响综合国力，必须经过人物利益、关系/派系结构、执行动作、国力维度四层。

### 3.9 特殊链路

#### 3.9.1 献策方向链

献策不是“只要成功就伤北周”。AI 会判断：

| 方向 | 结果倾向 |
|---|---|
| `pro_state` | 对北周整体有利，可能反而提高北周相关维度 |
| `pro_target_anti_state` | 对 NPC 个人/派系有利，但损北周整体，才会成为玩家想要的有效献策 |
| `neutral_or_vague` | 效果较弱，可能只有信任变化或轻微结构影响 |

这解决了早期问题：玩家写“请北周好好整顿军政”不应被系统当成有效伤国计。

#### 3.9.2 谶纬链

谶纬当前强调三件事：

1. 必须像灾异、征兆、谶辞，而不是普通政论。
2. 必须解释这如何指向名分裂缝、天命不稳或某类人可疑。
3. 若目标是地方军头，谶纬成功后更像“中枢疑心加重”，表现为削饷、军需收紧、监军加压，因此军力小幅下降、忠诚度更明显下降。

谶纬不吃信任加成，且有较强基础成功率空间，这是符合特色玩法定位的。

#### 3.9.3 设局嫁祸链

设局嫁祸不是“对目标说坏话”，而是要让目标：

1. 顺着玩家的话露出口风。
2. 说出让自己可疑、失态或失措的内容。
3. 最后嫌疑回落到自己身上。

因此 AI 会重点看 `selfTrapPotential` 与 `scapegoatClarity`。这两个字段越高，计谋越容易转化为恩宠/眷顾下降、派系受损、治理受损。

#### 3.9.4 朝堂处置链

当前处置链已经从“任意朝臣借刀处死任意朝臣”改成更合理的皇帝/太后双阈值：

1. 可被处置对象主要是朝堂关键人物，不包括地方军头。
2. 每个可处置朝臣有 `皇帝恩宠` 与 `太后眷顾`。
3. 谗言/离间通常根据听话者派系降低目标一侧态度。
4. 设局嫁祸/谶纬可以造成双侧较小幅度下降。
5. 当两侧态度低于罢黜阈值，可通过对实权人物借刀罢黜。
6. 当两侧态度更低，可通过借刀处决。
7. 罢黜/处决会造成预设的北周国力伤害，军事人物更伤军事维度。

#### 3.9.5 地方军头链

地方军头不走朝堂处决链，而走“忠诚、军力、信任、割据/造反”链：

| 数值 | 玩家视角含义 |
|---|---|
| 信任度 | 军头是否愿意听玩家的话，影响高阶计谋解锁 |
| 忠诚度 | 军头对北周中枢是否仍然服从，是割据/造反关键门槛 |
| 军力 | 军头可动用的实力，也影响其割据/造反后的国力冲击 |

割据/造反有硬条件，不是 AI 说成功就成功。条件包括信任、忠诚、暗线解锁、回合规则、目标状态等。

## 4. 二次追问回答判定链路

### 4.1 设计定位

二次追问不是第四个计谋，而是对原计谋的一次补充修正。它只允许小幅影响原计谋：

1. 补强说辞可信度。
2. 降低或增加暴露风险。
3. 小幅改变成功率。
4. 小幅改变成功后的效果倍率。

它不能绕过计谋类型、目标状态、解锁条件，也不能凭空制造新计谋。

### 4.2 输入给 AI 的上下文

追问解析 prompt 会提供：

| 上下文 | 用途 |
|---|---|
| 当前回合、事件、局势摘要 | 判断补充是否仍贴合时局 |
| NPC 姓名、官职、人设、立场、性格 | 判断是否顺着 NPC 的疑虑和利益 |
| 本回合计谋类型 | 防止把回复当成新计谋 |
| 原始说辞 | 判断补充是否在解释原计谋 |
| 原始解析 JSON | 让 AI 知道原计谋基础强弱 |
| NPC 追问 | 判断玩家是否回答了问题 |
| 玩家回复 | 核心输入 |

### 4.3 追问 JSON Schema

| 字段 | 范围 | 含义 |
|---|---:|---|
| `clarificationFit` | 0-1 | 是否澄清了原计谋的关键疑点 |
| `npcInterestFit` | 0-1 | 是否顺着 NPC 利益、立场、顾虑回答 |
| `pressureControl` | 0-1 | 是否控制住压力，没有逼得太露骨 |
| `contradictionRisk` | 0-1 | 是否与原说辞矛盾，或让 NPC 起疑 |
| `exposureRiskDelta` | -0.12 到 0.18 | 对暴露风险的小幅修正 |
| `successRateDelta` | -0.08 到 0.12 | 对成功率的小幅修正 |
| `effectMultiplierDelta` | -0.10 到 0.18 | 对成功后效果倍率的小幅修正 |
| `evidence` | 字符串数组 | 不超过 3 条依据 |

### 4.4 追问如何反作用到原计谋

若玩家回答了追问，系统会先 normalize 追问 JSON，再改写原计谋解析：

```text
characterFit +=
  (clarificationFit - 0.5) * 0.08
  + (npcInterestFit - 0.5) * 0.05
  - contradictionRisk * 0.03

eventFit +=
  (clarificationFit + npcInterestFit) * 0.03
  - contradictionRisk * 0.02

executability +=
  pressureControl * 0.06
  - contradictionRisk * 0.05

exposureRisk += exposureRiskDelta
```

随后：

```text
最终成功率 += successRateDelta
成功后效果倍率 *= 1 + effectMultiplierDelta
效果倍率 clamp 到 0.9 - 1.18
```

这意味着二次追问的影响是“窄幅修正”。即使玩家回答得很好，也只是让原计谋更顺手，不会凭空把弱计谋变成强计谋。

### 4.5 追问 fallback

如果 AI 失败，追问 fallback 会根据：

1. 回复长度。
2. 原计谋 `characterFit`、`eventFit`、`executability`、`exposureRisk`。
3. 是否有一定实质内容。

给出保守修正。当前 fallback 对长度有一定奖励，因此在断网时存在“长但空的回复被略微奖励”的可能。建议后续加入更严格的 substance check，例如必须命中原说辞、NPC 追问、利益词、行动词中的至少一类。

## 5. 女帝问政回答判定链路

### 5.1 设计定位

女帝问政页的 AI 判定对象不是北周 NPC，而是玩家给南陈女帝的附言。它决定：

1. 玩家是否理解本回合问政题目。
2. 选择的政策是否有清晰执行路径。
3. 是否考虑代价。
4. 是否贴合法统方向。
5. 本回合南陈五维变化的倍率。
6. 是否产生下一回合“问政余波”。
7. 是否影响战役动量。

### 5.2 什么时候调用 AI

当前逻辑：

| 情况 | 是否调用 AI | 结果 |
|---|---:|---|
| 玩家写了附言 | 是 | 解析附言，生成女帝回信，影响政策倍率与问政余波 |
| 玩家未写附言 | 否或只走默认 | 不调女帝 Agent 生成长回信；无问政余波 |

需要注意：即使玩家不写附言，玩家选择的政策选项本身仍会产生基础即时效果，只是缺少高质量附言带来的倍率提升和余波。

### 5.3 女帝问政 JSON Schema

| 字段 | 范围 | 含义 |
|---|---:|---|
| `focusAlignment` | 0-1 | 附言是否切中本题评分重点 |
| `executionClarity` | 0-1 | 是否给出可执行路径，不只是表态 |
| `costAwareness` | 0-1 | 是否考虑代价、风险、资源限制 |
| `legitimacyAlignment` | 0-1 | 是否贴合法统方向 |
| `policyStance` | 枚举 | 中性、均衡、激进、保守、权宜 |
| `evidence` | 字符串数组 | 不超过 3 条依据 |

Prompt 会提供问政母题、完整题目、玩家附言、法统方向、评分重点。

### 5.4 fallbackPolicyParse

如果 AI 不可用，会使用关键词 fallback：

| 字段 | fallback 依据 |
|---|---|
| `focusAlignment` | 是否命中评分重点、题目关键词、政策方向词 |
| `executionClarity` | 文本长度、是否有执行动作词 |
| `costAwareness` | 是否提到代价、风险、财政、粮草、民心、官吏阻力 |
| `legitimacyAlignment` | 是否贴合当前题目的法统方向 |
| `policyStance` | 根据用词判断激进、保守、均衡、权宜 |

### 5.5 即时政策效果公式

南陈五维即时变化来自玩家选择的选项基础效果，再乘以理由修正：

```text
reasonModifier =
  (
    0.7
    + focusAlignment * 0.4
    + executionClarity * 0.35
    + legitimacyAlignment * 0.18
  )
  * 回合阶段倍率

最后 clamp 到 0.62 - 1.68

最终政策变化 =
  选项基础五维变化
  * reasonModifier
  * 难度档政策即时倍率
```

回合阶段倍率：

| 回合 | 政策即时阶段倍率 |
|---:|---:|
| 1-6 | 0.74 |
| 7-12 | 0.90 |
| 13-20 | 1.04 |

当前 `costAwareness` 不进入即时政策效果，只进入问政余波。这是一个明确设计取向：本回合主要看是否切题、可执行、合乎法统；代价意识更多决定政策是否能延续。

### 5.6 问政余波公式

问政余波只在玩家写了附言时生成。其核心逻辑：

1. 只对本回合正向即时效果产生延续收益。
2. `costAwareness`、`legitimacyAlignment`、`focusAlignment` 越高，延续越强。
3. 治理维度有额外 tailwind，因为好的制度安排更容易延续。
4. 法统上升会额外增加治理和社会秩序。
5. 法统下降会额外扣社会秩序和治理。

公式简化如下：

```text
followUpFactor =
  (
    0.14
    + costAwareness * 0.16
    + legitimacyAlignment * 0.12
    + focusAlignment * 0.10
  )
  * 问政余波阶段倍率
  * 难度档余波倍率

followUpFactor clamp 到 0.12 - 0.52
```

问政余波阶段倍率：

| 回合 | 余波阶段倍率 |
|---:|---:|
| 1-6 | 0.50 |
| 7-12 | 0.82 |
| 13-20 | 1.00 |

自审：当前“无附言无余波”的规则是合理的，能鼓励玩家用自然语言参与 AI Native 玩法；但“无附言仍有选项基础即时效果”也合理，因为玩家至少做了政策选择。

## 6. 固定公式层：如何防止 AI 裁判失控

### 6.1 计谋解锁与目标合法性

在成功率之前，系统会先做硬条件判断：

| 条件 | 作用 |
|---|---|
| 计谋是否在当前回合开放 | 防止玩家提前使用特殊计谋 |
| NPC 是否存活或未终局 | 死亡、已罢黜、已割据/叛乱成功者不应继续作为普通目标 |
| 信任度是否达标 | 高阶计谋需要足够信任 |
| 暗线是否解锁 | 煽动割据/造反等需要足够情报 |
| 目标类型是否匹配 | 地方军头不走借刀处决链，朝堂角色不走割据链 |
| 借刀执行者是否合法 | 只有有处置权的实权人物能推动罢黜/处决 |

这些硬条件不会因为 AI 认为文本写得好就被绕过。

### 6.2 数值 clamp

当前使用多层 clamp：

| 层 | clamp 目标 |
|---|---|
| AI JSON 字段 | 0-1 或 -1 到 1 |
| 追问 delta | 小范围正负值 |
| 成功率 | 一般 0.05-0.98，谶纬 0.14-0.94 |
| 人物倍率 | 成功约 0.8-2.1，失败约 0.9-1.35 |
| 派系倍率 | 成功约 0.75-2.4，失败约 0.9-1.3 |
| 国力倍率 | 成功且结构穿透够高才放大，否则压低 |
| 国家五维 | 最终维度保持在系统合法范围 |
| NPC 信任、忠诚、军力 | 最终保持在 0-100 |

### 6.3 早期压缩与低风险压缩

系统对早期回合和低风险计谋有额外压缩：

1. 前 1-6 回合常规计谋国力影响显著压低。
2. 试探、普通献策等低风险计谋不应轻易造成大规模国力伤害。
3. 若结构穿透不足，即使计谋成功，也只给低国力倍率。

这与设计目标一致：普通玩家首通不应被前期数值波动吓到，同时也避免随便一句话就伤国。

### 6.4 关系记忆与处置链的收束

当前 NPC-NPC 关系记忆和长期记忆主要用于：

1. 让 NPC 回应更像记得旧账。
2. 让谗言/离间/借刀的后续反馈更连贯。
3. 给冯道之、NPC 回应和天道卷轴提供上下文。

但真正的处置结果仍由皇帝恩宠、太后眷顾、阈值与借刀合法性决定。记忆增强沉浸感，不直接绕过数值门槛。

| 链路 | AI 输入 | AI 输出 | 公式如何使用 | 最大风险 | 当前防线 |
|---|---|---|---|---|---|
| 北周计谋 | 回合、NPC、计谋、玩家说辞、关联对象 | 结构评分、方向字段、五维相关度 | 成功率、倍率、模板、国力维度选择 | 玩家关键词堆砌、AI 误判结构穿透 | clamp、fallback、transmission gate、早期压缩 |

## 8. 机制合理性自审

### 8.1 当前机制做得比较稳的地方

| 点 | 说明 |
|---|---|
| AI 不直接写最终数值 | 这是最大安全垫，避免 GameMaster 即兴发挥导致数值崩坏 |
| 每条链路都有 fallback | API 失败不阻断游戏，适合 Demo 和比赛环境 |
| 谶纬不吃信任加成 | 符合“公共玄学/舆论工具”的设计，不再像普通说服 |
| 献策有正负方向 | 解决了“利国献策却伤北周”的语义矛盾 |
| 设局嫁祸有专属字段 | 让它区别于谗言/离间，不再只是换皮挑拨 |
| 谗言/离间/借刀有传导门槛 | 私人坏话不应直接造成国力伤害 |
| 二次追问影响被限制 | 追问能提升沉浸感，但不会变成额外免费计谋 |
| 女帝问政余波需要附言 | 鼓励玩家参与 AI Native 玩法，而不是只点选项 |

### 8.2 发现的潜在逻辑漏洞

| 优先级 | 问题 | 影响 | 建议 |
|---|---|---|---|
| 高 | 结构化 system prompt 对 signed 字段有表述矛盾 | 模型可能不愿输出负数，影响 `stateBenefit` 等字段准确度 | 拆分 prompt 或改成“除特别标注字段外” |
| 高 | `chatCompletionJson` 只对截断 JSON 重试，不对“输出了散文/解释”做纠偏重试 | 模型偶发跑偏会直接 fallback，降低 AI Native 强度 | 增加一次“纠偏 JSON-only retry” |
| 中 | 北周 AI 若五维相关度全 0，会用 fallback 维度补齐 | 能防漏判，但也可能把 AI 有意判定为无关的文本重新 keyword 化 | 只在 AI evidence 为空或结构分足够高时补齐，或记录 debug 标记 |
| 中 | 追问 fallback 对长度有奖励 | 断网时长废话可能略微加分 | fallback 增加实质内容检查 |
| 中 | 女帝问政 `costAwareness` 不影响即时效果 | 好处是职责清晰；坏处是“考虑代价”只影响余波，玩家短期感知弱 | 可给即时倍率加很小权重，例如 `+ costAwareness * 0.08` |
| 中 | fallback 主要基于关键词 | 离线模式可玩，但容易被关键词堆砌 | 增加正则组合条件和负面模式，避免只靠单词命中 |
| 低 | 谶纬高基础成功率可能过强 | 特色玩法应该偏强，但需要避免成为唯一最优解 | 后续用真实输入样本观察谶纬在 3/8/13/14/15/19/20 的胜率贡献 |
| 低 | 女帝无附言仍有即时政策效果 | 合理但可能削弱写附言的必要性 | 可在 UI 上强调“附言决定走得多远和是否有余波” |

### 8.3 可以给第三方 Agent 重点审阅的问题

1. 北周计谋 JSON 字段是否过多，是否需要拆成“语义方向解析”和“数值相关解析”两步？
2. `stateBenefit / targetBenefit / advicePolarity` 是否足以判断献策的正反效果？
3. 谶纬对地方军头的“军力小降、忠诚大降”是否符合玩家直觉？
4. 设局嫁祸与谶纬在 prompt 层是否已经足够区分？
5. 二次追问的 delta 上限是否太保守，玩家会不会感受不到二次回答的价值？
6. 女帝问政的 `costAwareness` 是否应该影响即时效果，还是只影响余波更清晰？
7. fallback 是否应该明确标记到调试面板中，方便区分“AI 判定”和“本地兜底判定”？

## 9. 建议的下一步优化顺序

### 9.1 第一优先级：Prompt 与 JSON 可靠性

1. 修正结构化 system prompt 对 signed 字段的矛盾表述。
2. 增加一次 JSON-only 纠偏重试，而不只是截断重试。
3. 对三个 JSON schema 增加运行时 schema 校验，例如使用轻量 validator 或自写字段检查。
4. 在 dev/debug 模式记录“AI 原始输出、normalize 后 JSON、fallback 是否触发、最终公式输入”。

### 9.2 第二优先级：fallback 抗关键词堆砌

1. 北周 fallback 不只看关键词，还要看“人物/事件/行动”组合是否同时存在。
2. 追问 fallback 不只看长度，还要看是否回答了 NPC 的追问。
3. 女帝 fallback 对空泛政治口号降低 `executionClarity`。

### 9.3 第三优先级：数值体验微调

1. 观察谶纬在真实输入下是否明显强于其他计谋。
2. 观察二次追问是否有足够体感收益。
3. 观察南陈问政附言是否足以拉开“会写”和“不写”的差距。
4. 如果玩家仍不理解数值来源，可以在计谋筹算结果和《南北朝通鉴》卷轴中继续强化因果叙事。

## 10. 一句话总结

当前《佞臣》的 AI GameMaster 数值判定机制已经形成了比较稳的“受限裁判”框架：AI 负责理解文本，公式负责落数值，clamp 与 fallback 负责兜底。下一阶段最值得优化的不是让 AI 权限更大，而是让 JSON 解析更可靠、fallback 更抗刷词、prompt 对 signed 字段和特殊计谋的描述更精确。
