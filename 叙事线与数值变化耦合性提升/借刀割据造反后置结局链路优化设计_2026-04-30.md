# 借刀 / 割据 / 造反后置结局链路优化设计

## 一、为什么要单独优化这条链路

借刀、煽动割据、煽动造反和普通计谋最大的不同在于：它们真正有历史分量的结果，不完全发生在 `settleScheme` 当下，而是在回合结算后置阶段才最终落定。

- 借刀：先由计谋成功与 `proxyTransmission` 判定是否能推动收网，再由处置链判断结果是 `failed`、`pressure`、`dismissed` 还是 `executed`。
- 煽动割据：先让地方军头出现割据倾向，再根据军力、信任、忠诚和高危倾向判断是坐实割据，还是未敢明牌、暂观朝局。
- 煽动造反：先让地方军头起兵，再判断是击退平叛后割据一方，还是旋即被剿但仍造成北周兵粮折损。

这些最终 outcome 是玩家最应该感受到“历史被改写”的部分。如果 AI 后续润色 NPC 举措时把 outcome 写弱，玩家看到的就会从“祖廷被罢黜/处决”“安思明坐实割据/起兵被剿”退回成泛泛的“收紧手脚”“离心更重”，叙事冲击会明显下降。

## 二、当前代码现状

### 1. 后置结局已经产生并反写

当前已经有基础闭环：

- `src/game/roundSettlement.ts`
  - 借刀阶段调用 `resolveCourtDispositionProxy(...)`。
  - 外部军头阶段调用 `resolveExternalAction(...)`。
  - 得到 report 后分别调用 `attachBorrowedBladePostResolution(...)`、`attachExternalActionPostResolution(...)`。

- `src/game/schemePostResolutionEvent.ts`
  - `attachBorrowedBladePostResolution(...)` 会把借刀结果写入：
    - `result.npcAction.text`
    - `result.causalEvent.motionText`
    - `result.causalEvent.postResolutionEvent`
  - `attachExternalActionPostResolution(...)` 会把割据/造反结果写入：
    - `result.npcAction.text`
    - `result.causalEvent.motionText`
    - `result.causalEvent.postResolutionEvent`

- `src/game/schemeCausalEvent.ts`
  - `SchemePostResolutionEvent` 已有结构：
    - `kind: 'borrowed_blade' | 'external_action'`
    - `outcome`
    - `summary`
    - `actionMechanism`
    - `counterAction`
    - `damageMechanism`

也就是说，底层不是没有 outcome，而是 outcome 还没有变成 AI 举措 prompt 和 validator 的硬约束。

### 2. AI 举措目前主要通过 fallbackText 感知后置结局

当前 `src/ai/prompts/schemeNpcAction.ts` 中，AI 看到的是：

- 已定数值后果 `effectSummary`
- 本地兜底举措 `fallbackText`
- 必须解释的数值因果 `narrativeObligations`
- NPC 身份、派系、记忆、世界记忆等上下文

如果后置结局已经反写，那么 `fallbackText` 通常会包含“处决”“罢黜”“坐实割据”“旋即被剿”等字样。问题是：这只是普通文本素材，不是结构化硬规则。

因此 AI 可能发生三种偏移：

1. 保留了动作，但弱化最终 outcome
   例如 `executed` 被写成“压住祖廷旧部”，没有明确“祖廷已被处决”。

2. 保留了损失机制，但错过政治性质
   例如 `dismissed` 被写成“案牍受阻”，但没说“正式罢黜、府署被收、职权断档”。

3. 保留了地方军头动作，但混淆 outcome
   例如“旋即被剿”被写成“割据坐大”，或“割据”被写成公开称帝/彻底反周。

### 3. validator 还没有 outcome-specific 校验

当前校验主要覆盖：

- 是否提到行动 NPC。
- relatedNpc 显性受损时是否提到 relatedNpc。
- 主维度关键词是否命中。
- 是否泄露萧宝颖南陈身份。
- 是否出现宇文棣/贺拔琪等正典错称。
- 是否满足维度 obligation 的介质词和损失机制词。

这些能挡住很多普通错误，但对后置结局不够精确：

- `borrowed_blade.executed` 没有强制出现“处决/伏诛/收网”等结果词。
- `borrowed_blade.dismissed` 没有强制出现“罢黜/收权/府署被收”等结果词。
- `borrowed_blade.pressure` 没有强制禁止写成“已经处决/罢黜”。
- `external_action.secession` 没有强制禁止写成公开称帝或彻底反周。
- `external_action.rebellion` 没有按“击退平叛后坐大”与“旋即被剿但折损兵粮”区分结果。

这就是当前 P2 风险的核心：后置结局已有结构，但 AI 文案还没有被迫忠实继承这个结构。

## 三、理想效果

### 1. 借刀

借刀的叙事必须让玩家读出“处置链已经落定到了哪一步”。

- `failed`：没有真正借到刀，只形成虚张声势或反噬风险。
- `pressure`：执行者出面施压，但目标两边庇护尚未同时崩塌，不得写成正式罢黜或处决。
- `dismissed`：目标被正式罢黜，职权、府署、案牍或旧属被收。
- `executed`：目标被朝廷处决或收网，旧属、案牍、派系、政务因此断档。

理想文案例：

> 宗艾借帘前名义落下收网诏令，祖廷已被正式罢黜，度支旧案与中书案牍一并收归复核；祖廷旧属仓促切割，库藏支账与州县调度随之断档。

或：

> 贺拔琪虽出面压向宇文棣，但燕王尚未同时失去御前与宗室庇护，此事只在军议中添了一重疑云，尚未变成正式罢黜。

### 2. 煽动割据

割据不是公开称帝，也不是马上彻底反周。它的质感应是“仍奉北周名义，但地方开始另设调度”。

必须体现：

- 军头动作：扣留贡赋、另造军府簿籍、私署属官、拖延中枢调令、封锁关津。
- 北周反应：追索税粮、遣吏查问、派监军、封驿问责。
- 损失机制：财政收不上、粮道迟滞、诏令不通、州郡自雄。

理想文案例：

> 安思明仍称奉北周号令，却扣下卢龙贡赋，另造军府簿籍，拖延尚书省调令；中枢遣吏追索不得，河北转运与州县诏令因而迟滞。

### 3. 煽动造反

造反应升级为公开军事冲突，但不同 outcome 要写出不同结果。

- 击退平叛军：地方军头坐大，北周必须正面应对明旗反周之势。
- 旋即被剿：地方军头失败或死亡，但北周仍为平叛折损兵粮、军令改道、州县震动。

理想文案例：

> 安思明截断入京驿路，发檄起兵，先据两处关津；平叛军虽将其旋即剿灭，却不得不抽调河北兵粮，军令改道，州县为之一震。

或：

> 安思明击退第一路平叛军后据守卢龙，明旗反周之势已成；北周被迫改调边军，兵粮、军令与地方秩序一并受损。

## 四、应该怎么改

### 改法 1：把 postResolutionEvent 结构化注入 AI prompt

不要只把后置结局塞进 `fallbackText`，而是在 `buildSchemeNpcActionPrompt(...)` 增加显式字段，例如：

```ts
postResolutionEvent?: SchemePostResolutionEvent | null
```

然后在 prompt 中新增一段“后置结局硬事实”：

```text
后置结局硬事实：
- 类型：借刀收网 / 外部军头行动
- 最终结果：executed / dismissed / pressure / secession / rebellion
- 已定摘要：...
- 必须保留动作：处决、收网、罢黜、扣留贡赋、起兵、被剿...
- 必须解释损失：职权断档、派系震动、转运迟滞、兵粮折损...
硬规则：这部分是已结算事实，AI 不得弱化、反转或省略。
```

关键点：

- `fallbackText` 仍保留，但降级为“自然语言参考”。
- `postResolutionEvent` 才是硬事实来源。
- AI 可以改写句式，但不能改写 outcome。

### 改法 2：扩展 prompt context，让 AI 明确“必须保留 outcome”

新增 helper，建议放在 `src/ai/prompts/schemeNpcAction.ts` 或独立 helper：

```ts
function formatPostResolutionPromptBlock(event: SchemePostResolutionEvent | null | undefined): string
```

它根据事件类型输出不同要求：

- `borrowed_blade + executed`
  - 必须写明目标已被处决/伏诛/收网。
  - 必须提旧属、案牍、府署、派系或政务断档。

- `borrowed_blade + dismissed`
  - 必须写明目标已被罢黜/收权。
  - 必须提职权、府署、案牍或人手被收。

- `borrowed_blade + pressure`
  - 必须写明只是施压。
  - 禁止写成处决、罢黜、伏诛。

- `external_action + secession`
  - 必须写明仍奉北周名义或未敢明牌。
  - 必须出现扣贡赋、另设调度、私署属官、拖延调令、封锁关津等至少一类。
  - 禁止公开称帝、彻底反周。

- `external_action + rebellion`
  - 必须写明起兵、截驿、发檄、据关、平叛等军事冲突。
  - 若 summary 含“旋即被剿”，必须写失败但北周折损。
  - 若 summary 含“击退平叛”，必须写地方坐大或割据一方。

### 改法 3：新增 postResolutionEvent 专属 validator

新增纯函数，建议放在 `src/game/schemePostResolutionEvent.ts` 或新文件 `src/game/schemePostResolutionValidation.ts`：

```ts
export function validatePostResolutionNarrative(input: {
  text: string
  postResolutionEvent?: SchemePostResolutionEvent | null
}): { accepted: boolean; reasons: string[] }
```

校验规则建议：

#### borrowed_blade

`outcome === 'executed'`

- 必须命中：`处决|伏诛|收网|落下最后一手|弃市|赐死`
- 禁止只写：`施压|暂且|尚未|只添压力`
- 失败原因：`missing_executed_outcome`

`outcome === 'dismissed'`

- 必须命中：`罢黜|免职|夺职|收权|府署被收|案牍被收`
- 禁止写：`处决|伏诛|赐死`
- 失败原因：`missing_dismissed_outcome` / `overstated_execution`

`outcome === 'pressure'`

- 必须命中：`施压|添压力|尚未|庇护未崩|未能收网`
- 禁止写：`处决|罢黜|伏诛|正式收网`
- 失败原因：`pressure_overstated_as_disposal`

#### external_action secession

- 必须命中动作词：`扣留贡赋|另造|私署|拖延调令|封锁关津|自设调度|州郡自雄`
- 必须命中非公开反周边界：`仍奉|未敢明牌|名义上|暂观朝局`
- 禁止：`称帝|建国|彻底反周|明旗反周`
- 失败原因：`missing_secession_mechanism` / `secession_overstated_as_rebellion`

#### external_action rebellion

- 必须命中军事冲突词：`起兵|发檄|截断驿路|据守关隘|平叛|被剿|击退`
- 如果 summary 含“旋即被剿”：
  - 必须命中：`被剿|旋即|未坐大|折损兵粮`
  - 禁止写成：`割据一方|坐大`
- 如果 summary 含“击退平叛”：
  - 必须命中：`击退|割据一方|明旗反周|正面应对`
- 失败原因：`missing_rebellion_conflict` / `rebellion_outcome_reversed`

### 改法 4：把 validator 接入现有 AI 举措校验链

当前 `src/ai/schemeNpcActionOrchestrator.ts` 的 `validateGeneratedSchemeNpcActionText(...)` 已经合并：

- `validateSchemeNpcActionNarrative(...)`
- `validateSchemeCausalEvent(...)`

应新增：

```ts
const postResolutionValidation = validatePostResolutionNarrative({
  text,
  postResolutionEvent: task.result.causalEvent?.postResolutionEvent,
})
const reasons = unique([
  ...narrativeValidation.reasons,
  ...causalValidation.reasons,
  ...postResolutionValidation.reasons,
])
```

这样 AI 如果把“处决”写弱成“施压”，或把“旋即被剿”写成“割据坐大”，会被拒绝并保留 fallback。

### 改法 5：纠错重试 prompt 增加后置结局原因说明

现有 correction prompt 已能根据 `missing_damage_mechanism_*` 做一次纠错。应补上后置结局错误原因：

```text
- missing_executed_outcome：必须写明目标已被处决/伏诛/收网。
- missing_dismissed_outcome：必须写明目标已被罢黜/收权。
- pressure_overstated_as_disposal：这是施压，不得写成处决或罢黜。
- secession_overstated_as_rebellion：割据仍奉北周名义，不得写公开称帝或彻底反周。
- rebellion_outcome_reversed：不得把“旋即被剿”写成坐大，也不得把“击退平叛”写成失败。
```

首版仍保持“一次纠错重试”，不增加更多请求次数。

### 改法 6：保留 fallback 的结构化质量

fallback 在这条链路里很重要，因为它是最稳定的正本。

建议优化 `attachBorrowedBladePostResolution(...)` 和 `attachExternalActionPostResolution(...)` 的 fallback 文本，让它本身就满足 validator：

- 借刀 fallback 要区分 `pressure` / `dismissed` / `executed`，而不是统一追加“旧属与案牍断档”。
- 割据 fallback 要区分“坐实割据”与“未敢明牌”。
- 造反 fallback 要区分“击退平叛后割据一方”与“旋即被剿但折损兵粮”。

这样即使 AI 被拒绝，玩家看到的 fallback 也不是泛化文本。

## 六、测试计划

### 1. 后置结局 fallback 测试

目标：本地 fallback 本身就能正确表达 outcome。

覆盖：

- 借刀 pressure：必须写“施压/尚未失去两边庇护”，不得写“罢黜/处决”。
- 借刀 dismissed：必须写“罢黜/收权/府署或案牍被收”，不得写“处决”。
- 借刀 executed：必须写“处决/收网”，并写旧属、案牍、派系或政务断档。
- 割据坐实：必须写仍奉名义但实际割据。
- 割据未明牌：必须写未敢明牌、暂观朝局，但离心和调度损耗存在。
- 造反击退平叛：必须写击退平叛、割据一方或明旗反周。
- 造反旋即被剿：必须写被剿但北周折损兵粮，不得写坐大。

### 2. 后置结局 validator 测试

目标：AI 文案不能弱化或反转 outcome。

覆盖：

- `executed` 文案只写“施压” -> 拒绝。
- `dismissed` 文案写成“处决” -> 拒绝。
- `pressure` 文案写成“正式罢黜” -> 拒绝。
- `secession` 文案写“公开称帝” -> 拒绝。
- `rebellion` summary 是“旋即被剿”，文案写“割据坐大” -> 拒绝。
- 合格文本 -> 通过。

### 3. AI 举措 orchestrator 测试

目标：AI patch 只有在保留后置 outcome 时才能替换 fallback。

覆盖：

- AI 返回合格 `executed` 文案 -> 替换 `npcAction.text` 与 `causalEvent.motionText`。
- AI 返回弱化 `executed` 文案 -> 拒绝，保留 fallback。
- AI 首次失败、纠错后补回 outcome -> 通过。
- 数值字段保持完全不变。

### 4. 通鉴与世界记忆回归

目标：后置结局被 AI 替换后，记忆和通鉴仍使用同一事实。

覆盖：

- `updateSchemeNpcAction(...)` 后，`npcMemoryLedger`、`relationMemoryLedger`、`worldMemoryLedger` 同步 patch。
- 《南北朝通鉴》优先读 `causalEvent.motionText`，不得把处决写成施压，不得把被剿写成坐大。

## 七、风险与取舍

### 风险 1：validator 过严导致 AI 文案更常被拒

这是可接受风险。借刀、割据、造反是高叙事权重事件，宁可保留稳定 fallback，也不应让 AI 改写 outcome。

### 风险 2：关键词校验可能误杀古雅表达

解决方式不是放弃校验，而是扩充同义词：

- 处决：处决、伏诛、弃市、赐死、收网、落下最后一手。
- 罢黜：罢黜、免职、夺职、收权、府署被收。
- 被剿：被剿、平灭、旋即败亡、未及坐大。

### 风险 3：prompt 变长

后置结局 block 只在 `postResolutionEvent` 存在时注入。普通计谋不增加 prompt 负担。

### 风险 4：地方军头 outcome 现在是中文 summary，不是更细枚举

当前 `ExternalActionReport` 只有 `action: 'secession' | 'rebellion'` 和中文 `outcome`。首版可以用 summary 关键词区分：

- `坐实地方自雄` / `已成割据`
- `未敢明牌` / `暂观朝局`
- `击退平叛`
- `旋即为平叛军所剿`

后续如果需要更稳，可以把 `ExternalActionReport` 增加内部枚举：

```ts
outcomeKind:
  | 'secession_established'
  | 'secession_hesitated'
  | 'rebellion_established'
  | 'rebellion_crushed'
```

但首版不必急着改类型，避免扩大存档/测试影响面。

## 八、建议实施顺序

1. 先写 `validatePostResolutionNarrative(...)` 的失败测试。
2. 实现 validator。

- AI 文案可以润色、扩写、人物化，但不能弱化、反转或省略这些已定 outcome。
