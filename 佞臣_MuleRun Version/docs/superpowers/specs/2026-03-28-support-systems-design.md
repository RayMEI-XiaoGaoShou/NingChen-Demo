# 《佞臣》支撑系统深化设计

**日期**：2026-03-28

## 1. 目标

在不推翻当前主循环的前提下，补齐 6 个会直接提升可玩性、可理解性与可复盘性的支撑系统：

1. 问政题库深度落地
2. 历史辅助层
3. 复盘 / 战报
4. 新手引导
5. 势力崩盘阈值接入主流程
6. 存档 / 续局

本轮设计原则：

- 不做大拆重构，优先沿用现有状态机与结算结构
- 所有新能力先做最小可行版本，再决定是否扩展
- 让玩家“更能看懂、更能判断、更能回顾”，而不是单纯增加信息量

---

## 2. 已确认的设计决策

### 2.1 问政字段如何真正落地

`legitimacyEffect`

- 不单独新增“第六条法统数值”
- 先作为轻量“法统后效标签”使用
- 主要影响：
  - 女帝回批的口风与稳定度
  - 下一回合延迟反馈的正负面倾向
  - 对南陈 `governance / socialOrder` 的修正倍率

`nextRoundFeedback`

- 不替代本回合问政回批
- 本回合问政回批：回答“女帝本回合如何批答”
- `nextRoundFeedback`：回答“这条政策到下一回合冒出了什么后效”
- 呈现在下一回合首页的南陈政务跟进区

`aiScoringFocus`

- 定义每道题真正看重的理由维度
- 用来决定玩家文字输入的加成是否命中重点
- 首批重点维度：
  - 缓急
  - 代价
  - 执行路径
  - 地方阻力
  - 财政承受力
  - 军政配套

### 2.2 历史辅助层的实现方式

- 第一版不依赖外部美术资源，不要求用户先提供参考图
- 先做“功能型辅助层”：
  - 每回合事件补地理与势力解释
  - 极简地图示意
  - 朝堂 / 外部势力关系示意
- 若后续需要更强历史质感，再考虑引入参考图或图像生成工具

### 2.3 势力崩盘阈值的接法

- 采用“软接入”，不直接改成硬终局条件
- 分两层：
  - `崩口`：触发额外惩罚与结算提示
  - `崩盘`：触发更重的结构性后果，但仍不直接终止主循环
- 不把它做成“一崩就死局”

### 2.4 新手引导方向

- 第一回合做成“半引导回合”
- 不强脚本锁死，只做更清晰的分步提示
- 必须明确讲清：
  - 世界观与主角身份
  - 核心目标
  - 各系统逻辑
  - 玩家文字输入的真实作用

---

## 3. 范围边界

本轮做：

- 现有问政系统的深度化
- 信息理解层与辅助解释层
- 一局结束后的复盘层
- 回合 1 的半引导
- 势力崩盘软接入
- 基础存档 / 续局

本轮不做：

- 全图地图系统
- 多存档位高级管理
- 复杂教程关卡脚本
- 问政新增第六维数值
- 势力崩盘直接导向硬失败

---

## 4. 方案概览

### 4.1 问政系统深度化

#### 4.1.1 新增结算层

现有问政结算流程：

`题库选项 -> 五维变化 -> 本回合回批`

升级后：

`题库选项 -> AI Scoring Focus 修正 -> legitimacyEffect 修正 -> 五维变化 -> 本回合回批 -> 下一回合后效反馈`

#### 4.1.2 legitimacyEffect 的轻量实现

每题每个选项已有：

- `up`
- `steady`
- `down`

落地规则：

- `up`
  - 本回合回批更正面
  - 下一回合后效更稳定
  - 对 `governance / socialOrder` 的负面回冲更低
- `steady`
  - 仅按题库原值与理由修正执行
- `down`
  - 即使短期收益不错，也更容易在下一回合出现执行阻力、名分损耗或地方反弹

实现方式：

- 不新增全局状态条
- 在 `policyReport` 基础上新增一个 `policyMomentum / policyLegitimacyTone` 结构
- 由结算页与下一回合首页读取

#### 4.1.3 nextRoundFeedback 的实现

新增“南陈政务跟进”区块：

- 位置：下一回合首页
- 内容：上一回合政策的延迟后效
- 表现形式：
  - 一段 1~2 句总结
  - 若有后效数值，则附 1~2 条微弱修正

示例口径：

- “盐政虽行，地方豪强已露推诿之态。”
- “减赋之令安抚人心，然国库进项一时转薄。”

#### 4.1.4 aiScoringFocus 的实现

每道题的理由评分不再是通用命中词，而是按题目关注点来判。

例如：

- `缓急`
  - 看是否提到先后次序、阶段推进
- `代价`
  - 看是否承认财政/门阀/军心成本
- `执行路径`
  - 看是否写出如何落地

首版实现：

- 每个 `aiScoringFocus` 对应一组关键词与句式命中规则
- 命中则在原先文字修正倍率上再加一层定向加成

### 4.2 历史辅助层

#### 4.2.1 回合事件辅助解释

当前已有“朝局简报”。

新增三类辅助信息：

- `地理提示`
  - 如河西、淮南、河北分别在哪里
- `势力提示`
  - 这件事更关系朝堂、边镇、草原还是地方豪强
- `战略提示`
  - 它为什么会影响南征 / 安内 / 国力

显示方式：

- 首页事件卡内折叠展示
- 用短段落，不做百科式长文

#### 4.2.2 极简地图示意

首页右侧或事件区下方新增简图：

- 北周都城
- 淮南
- 河北
- 河西 / 陇右
- 草原方向
- 南陈

不是历史地图复原，而是“帮助理解事件地理位置”的示意图。

#### 4.2.3 势力关系示意

新增一张简化关系图例：

- 朝堂：帝党 vs 后党
- 外部：陇右、草原、地方
- 玩家位于朝堂中枢缝隙

用途：

- 服务新手理解
- 服务每回合快速重新进入状态

---

### 4.3 复盘 / 战报

#### 4.3.1 目标

让一局结束后，玩家知道：

- 自己是怎么赢 / 输的
- 哪些决策最关键
- 哪些人物最常被利用或最危险

#### 4.3.2 最小可行版本

终局后新增“本局战报”模块，包含：

1. 关键转折
   - 关系结构失衡次数
   - 外部人物明牌次数
   - 是否触发过提前南征危机
2. 南北国力终局摘要
3. 关键人物互动统计
   - 最常施计对象
   - 试探最成功人物
4. 问政摘要
   - 采纳了哪些类型的治国路线

#### 4.3.3 数据来源

- `currentSchemes`
- `lastSettlement`
- 历回合结算快照

因此需要在 store 中新增：

- `roundHistory[]`

每回合结束时写入轻量快照。

---

### 4.4 新手引导

#### 4.4.1 第一回合 = 半引导回合

回合 1 不做强制教程，而是“引导层增强”：

- 冯道之给更明确的目标提示
- 页面顶部提示当前建议操作顺序
- 可用计谋暂收敛到最基础的几种
- 女帝问政页明确解释“理由会影响效果”

#### 4.4.2 引导内容结构

引导拆成 5 块：

1. `背景`
   - 你是萧宝颖
   - 潜伏北周
   - 与南陈女帝、冯道之的关系
2. `目标`
   - 保全自身
   - 阻止提前南征
   - 削弱北周
   - 扶南陈新政
3. `北周线`
   - 看朝局
   - 找关键人物
   - 下计
4. `南陈线`
   - 问政会提升南陈
   - 文字解释会影响效果
5. `AI Native`
   - 补一句说辞不是 flavor
   - 会影响成功率与效果链

#### 4.4.3 UI 形式

首版不做复杂教学弹窗树。

采用：

- 首页引导卡
- 朝局观察顶部说明条
- 问政页提示块
- 可关闭但可再次查看的“新手手札”

---

### 4.5 势力崩盘阈值接入主流程

#### 4.5.1 当前问题

`checkFactionCollapse()` 已存在，但没有真正接入回合结算与页面反馈。

#### 4.5.2 接入方式

在每回合结算末尾加入：

1. 判断是否出现 `崩口`
2. 若已连续或严重，则判断为 `崩盘`

建议阈值口径：

- `崩口`
  - 军事实力 <= 20
  - 或朝堂影响 <= 18
  - 或内部稳定 <= 18
- `崩盘`
  - 军事实力 <= 10
  - 或朝堂影响 <= 10
  - 或内部稳定 <= 10

#### 4.5.3 主流程后果

`崩口`

- 在结算页警示
- 对应 faction 下回合承受额外自然衰减
- 相关 NPC 更易离心

`崩盘`

- 判官明确点出
- 南征 / 安内压力重新计算
- 可能放大外部人物割据 / 造反倾向
- 终局报告把它作为关键成因

不会做：

- 崩盘即刻终局

---

### 4.6 存档 / 续局

#### 4.6.1 目标

20 回合游戏必须允许中断后回来继续。

#### 4.6.2 首版方案

采用本地单存档：

- 自动存档
  - 每回合进入 `ROUND_START`
  - 每回合完成 `SETTLEMENT`
- 手动“继续上局”
  - 标题页检测到存档则显示

#### 4.6.3 存档内容

存入 `localStorage`：

- 当前 round / phase
- 南北五维
- NPC 状态
- 势力状态
- 关系边状态
- intelProgress
- currentSchemes
- lastSettlement
- roundHistory
- endingReport（若已结束）

#### 4.6.4 约束

- 先做单存档位
- 不做多档管理
- 不做跨设备同步

## 6. 风险与控制

### 6.1 风险

- 历史辅助层做太重会挤压首页信息密度
- 问政后效若数值过强，会抢北周线存在感
- 崩盘阈值若做成硬失败，会破坏主循环
- 存档若直接保存过多临时 UI 状态，容易出现兼容问题

### 6.2 控制方式

- 历史辅助层首版只做功能型轻信息
- 问政后效保持“小幅度、重提示”
- 崩盘只做软接入
- 存档只保存“规则状态”，不保存瞬时 UI 展开态

---

## 7. 推荐实现顺序

1. 问政题库深度落地
2. 势力崩盘阈值接入主流程
3. 新手引导
4. 历史辅助层
5. 存档 / 续局
6. 复盘 / 战报

原因：

- 问政与崩盘直接影响规则闭环
- 新手引导与历史辅助层直接影响上手质量
- 存档是长局体验底线
- 复盘/战报依赖前面新增的数据沉淀，适合后接

---

## 8. 完成标准

当以下条件满足时，可视为本轮完成：

- 问政系统已真正消费 `legitimacyEffect / nextRoundFeedback / aiScoringFocus`
- 首页已有足够理解事件的历史辅助层
- 回合 1 已成为可完成的半引导回合
- 势力崩盘已进入结算、判官与终局报告
- 游戏可中断后续局
- 终局后可查看基础复盘/战报
