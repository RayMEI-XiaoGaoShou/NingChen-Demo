# 《佞臣》封面全屏动态壁纸改造设计

日期：2026-04-11

## 背景

当前封面页已经接入视频背景，但整体结构仍然是“应用壳层 + 页面内容卡片”的组合：
- 顶部仍有全局 `app-header`，包含小标题与静音按钮。
- 主内容区仍有统一的 `app-content` 留白与版心宽度约束。
- 封面组件自身仍是一个带圆角的内容容器，使用 `min-height: calc(100vh - 120px)`，因此视频只填充容器，而不是填满整个视口。

实际体验结果就是：即便中间区域已有动态背景，屏幕四周仍会出现黑框、顶部带状栏和中间大图卡片感。这与目标中的“全屏都是动态壁纸，交互元素直接压在背景上”不一致。

## 目标

### 体验目标

- 首屏封面应成为真正的全屏动态壁纸场景，而不是被包在页面卡片里。
- 左下角保留大标题 `佞臣`、副文案、`开始游戏`、`加载存档` 与存档提示。
- 右上角保留静音按钮，但它应悬浮在视频背景上，而不是依附于全局顶部栏。
- 点击 `开始游戏` 后，难度选择交互保持现状，继续在左下内容区展开。

### 视觉目标

- 去掉顶部小标题与顶部 header 对封面的干扰。
- 去掉封面外层黑边、圆角大卡片与额外纵向留白。
- 视频使用真正的全屏 `object-fit: cover` 铺满视口。
- 通过左重右轻的遮罩和布局，保证文案与按钮在动态画面上仍然清晰易读。

## 方案对比

### 方案 A：封面阶段切换到独立全屏壳层（推荐）

做法：
- 在 `prologueStep === 'COVER'` 时，应用切换到封面专用布局。
- 不渲染通用顶部 header，不套用通用 `app-content` 外边距。
- `Cover` 组件直接占满视口，并自行渲染悬浮静音按钮与左下内容区。

优点：
- 最符合“全屏动态壁纸”的目标。
- 结构最清晰，封面状态与游戏内页面状态职责分离。
- 后续如果要继续扩展封面特效、粒子、Logo 动画，空间更充足。

缺点：
- 需要对 `App.tsx` 做条件化布局调整。
- 需要把静音按钮从全局 header 迁移到封面页内。

### 方案 B：保留应用壳层，只扩大封面容器

做法：
- 继续保留 header 和通用主内容布局，只把封面容器改得更大、更贴边。

优点：
- 改动较少。

缺点：
- 顶部 header、小标题、黑边与版心感仍然存在。
- 无法彻底实现“全屏都是动态壁纸”。

### 结论

采用方案 A。

## 交互与布局设计

### 应用层布局

- `COVER` 阶段使用封面专属布局：
  - 不渲染当前的全局 `app-header`。
  - 主内容不使用通用 `app-content` 的上下 padding。
  - `GlobalAudio` 与其他游戏级组件仍保持加载，避免破坏音频行为。
- 非 `COVER` 阶段继续使用现有应用壳层，不影响其他页面。

### 封面层结构

封面页面分为三层：

1. 视频底层
   - 使用新的 `封面v2.mp4` 作为背景。
   - 视频全屏铺满容器，`object-fit: cover`。
   - 默认 `muted`，循环播放，支持 `playsInline`。

2. 可读性遮罩层
   - 左侧较深、右侧较轻的横向渐变。
   - 叠加轻微纵向暗角，防止亮部视频影响文字可读性。

3. 悬浮 UI 层
   - 右上角：静音按钮。
   - 左下角：大标题、年代短句、副文案、主要动作按钮、存档提示。
   - 难度面板：沿用现有切换逻辑，在同一内容区内替换展开。

### 文案与控件保留策略

- 保留左下角大标题 `佞臣`。
- 保留 `十年长局 二十回合` 的短句。
- 保留当前副文案与开始 / 读取存档逻辑。
- 取消顶部小标题，不再在封面阶段重复出现一套较小 Logo。

## 响应式设计

### 桌面端

- 内容区锚定左下角，控制最大宽度，避免遮挡过多视频主体。
- 静音按钮固定在右上角安全区内。

### 移动端 / 窄屏

- 仍保持全屏壁纸。
- 左下内容区改为更紧凑的窄栏布局，减小标题字号与按钮宽度。
- 难度面板宽度收敛到视口安全范围内。
- 保证按钮与文案不会超出屏幕底边或右边。

## 实现边界

### 允许修改

- `src/App.tsx`
- `src/components/Cover/Cover.tsx`
- `src/components/Cover/Cover.css`
- 与封面资源接入相关的静态资源目录
- 针对封面布局行为的测试文件

### 不改动

- 其他非封面页面的布局与视觉
- 游戏阶段流转逻辑
- 难度选择的状态逻辑与规则内容
- BGM 状态管理机制本身

## 测试设计

### 行为测试

- 为 `COVER` 阶段补一个最小测试，确认该阶段不再渲染通用顶部 header 文案。
- 确认封面仍能正常切换到难度选择面板。

### 手动验证

- 本地预览中确认封面视频可播放且铺满视口。
- 确认顶部黑框与小标题消失。
- 确认静音按钮位于视频上方而非独立 header 内。
- 确认切换难度面板后仍在左下内容区展开。
- 确认窄屏下无明显溢出。

## 风险与处理

### 风险 1：封面与非封面页面共用 App 布局，改动后误伤其他页面

处理：
- 将布局调整严格限定在 `prologueStep === 'COVER'` 条件内。

### 风险 2：新视频资源路径接入后在 Vite 中无法正确加载

处理：
- 将视频文件放入项目静态资源可访问位置，避免引用用户桌面绝对路径。

### 风险 3：动态背景导致文字可读性下降

处理：
- 使用更明确的左侧暗遮罩和轻微底部暗角。
- 保留按钮自身的高对比度样式。

## 成功标准

- 封面阶段打开时，用户看到的是全屏动态壁纸，而不是中间大图卡片。
- 顶部小标题和顶部 header 不再出现在封面阶段。
- 左下角的大标题与按钮保留，且层次清晰。
- 静音按钮悬浮在视频背景上。
- 难度选择仍沿用现有交互方式，不引入新的流程成本。
