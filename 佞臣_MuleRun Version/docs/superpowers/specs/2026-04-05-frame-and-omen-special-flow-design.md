# 《佞臣》设局嫁祸与谶纬专项流程设计

日期：2026-04-05  
范围：`MuleRun Version` 数值分支  
状态：设计稿

## 1. 背景

在上一轮“计谋语义与 UI 对齐”中，已经确认：

- `frame` 不适合继续以“放风构陷”这一玩家语义存在
- 更适合重定义为 `设局嫁祸`
- `omen` 不应只是“更神秘的离间”

进一步讨论后，又出现了两个更具体的问题：

1. `设局嫁祸` 是否需要像 `advise` 那样拥有一层专属附加框架
2. `谶纬` 是否应该拥有不同于普通计谋的专属施计流程

本设计专门回答这两个问题。

## 2. 当前链路的问题

### 2.1 `frame` 当前仍是“通用 parse + 固定负面模板”

当前 `frame` 的结算逻辑大致是：

- 玩家选一个 NPC
- 输入一句话
- AI / fallback 按通用北周 parse 解析
- 结算时对该目标本人施加固定的负面影响

这意味着：

- 它虽然机制上已经更像“目标本人背锅”
- 但语义上还没有真正回答：  
  **为什么这句话会让他自己失言、失态、误判，最后掉进局里**

换句话说，`frame` 还缺一层：

- 这句话是否真的具有“诱其入局”的性质

### 2.2 `omen` 仍然共享单段普通施计流程

当前谶纬仍然是：

- 选人
- 输入一段话
- AI 判它是否像谶纬

这会导致两个问题：

1. 玩家难以掌握谶纬写法  
   因为“什么算谶纬”没有被流程本身教出来。

2. AI 也更难稳定判断  
   因为缺少“征兆/谶辞”与“解释/指向”的结构分隔。

## 3. 设计目标

本轮目标不是调数值，而是让这两种计谋在结构上更像它们应该有的样子。

### `设局嫁祸`

目标：

- 保留当前单目标交互
- 保留当前“目标本人出事”的机制方向
- 但补一层更明确的专项语义判断：  
  **这句话是否真能让目标自己掉进局中**

### `谶纬`

目标：

- 给玩家更强的“怎么写”引导
- 给 AI 更稳定的结构化判定入口
- 把谶纬与离间的边界固化进流程本身，而不只是文案说明

## 4. `设局嫁祸` 的专项框架

### 4.1 结论

`设局嫁祸` 需要专项附加框架，但不需要像 `advise` 那样做完整 polarity。

原因：

- `advise` 的核心问题是方向性：利国还是利人害国
- `设局嫁祸` 的核心问题不是方向性，而是：  
  **这句话是否真的会让目标本人自己背锅**

因此推荐做窄而专的专项字段。

### 4.2 新增语义字段

建议在 `NorthSchemeParseResult` 中为 `frame` 增加：

- `selfTrapPotential: number`
  - 这段话是否真的容易诱导目标失言、失态、误判

- `scapegoatClarity: number`
  - 这段话是否清晰地把风险、责任或嫌疑最终回落到目标本人身上

### 4.3 判断逻辑

高质量 `设局嫁祸` 应满足至少两层：

1. **诱因成立**
   - 目标会被这段话刺激、误导或逼到失衡
   - 例如急于自辩、越描越黑、过度表态、急于站队、抢着甩锅

2. **结果回落到目标本人**
   - 这不是“让他怀疑别人”
   - 也不是“借他去害别人”
   - 而是让他自己成为最可疑、最难解释、最容易背责的那个人

### 4.4 典型高质量输入

- “此事若此刻急着澄清，旁人反倒会觉得你心虚。”
- “真把这层口风压得太快，最后最像知道内情的人，反而成了你。”

### 4.5 典型低质量输入

- 泛泛威胁
- 普通离间句式
- 只是让目标怀疑别人，却没有把锅落回目标自己

例如：

- “再这样下去别人会害你。”  
  这更像离间或谗言。

## 5. `谶纬` 的专属双段流程

### 5.1 结论

推荐给 `omen` 引入专属双段输入流程。

流程：

1. 选择 NPC
2. 输入 `谶辞 / 征兆`
3. 输入 `解释 / 指向`
4. AI 结构化判定
5. 结算

### 5.2 为什么值得做

#### 对玩家

它会直接把谶纬的写法教出来：

- 先给征兆
- 再解释名分裂缝
- 再暗示谁值得警惕

#### 对 AI

它会让判定更稳定：

- 第一段负责“这是不是谶纬”
- 第二段负责“它是在稳合法性，还是裂合法性”

### 5.3 双段定义

#### 第一段：谶辞 / 征兆

要求：

- 必须像灾异、征兆、谶语、异象、天命征候
- 不要求死板关键词匹配
- 但若完全只是普通政治话术，不应被判为高质量谶纬

示例：

- “石人一只眼，挑动黄河天下反。”
- “黄河有鱼跃龙门，龙气外泄，河北大旱。”

#### 第二段：解释 / 指向

要求：

- 解释该征兆意味着什么
- 必须触及：
  - 名分
  - 法统
  - 天命
  - 越分侵权
  - 局势失正  
  这类合法性裂缝中的至少一层

- 最后可进一步暗示：
  - 哪类人最该警惕
  - 哪条关系线最不稳

示例：

- “此非独天灾，恐是朝中名分失序之兆。若仍有人越分侵权，民间自会把灾异与人事相连。”

### 5.4 新增语义字段

建议在 `NorthSchemeParseResult` 或 `omen` 专属解析结果中增加：

- `omenAnchorStrength`
  - 第一段是否真的是有效征兆/谶辞

- `legitimacyCrack`
  - 第二段是否真正解释出了名分/法统/天命裂缝

- `suspicionDirection`
  - 第二段是否把怀疑有控制地引向某条关系线、某类权力角色或某种结构风险

### 5.5 与离间的流程区分

离间的结构更像：

- “谁会先害你 / 谁会先甩锅 / 谁在抢你位置”

谶纬的结构则应是：

1. 先给出征兆
2. 再解释名分裂缝
3. 最后暗示警惕对象

如果没有第 1 步，原则上不应被视为高质量谶纬。

## 6. 是否应当强制“必须玄学相关”

结论：**应当强约束，但不应机械关键词匹配。**

也就是说：

- 流程上，应要求先输入 `谶辞/征兆`
- 判定上，应要求它在语义上像征兆、灾异、异象、谶语
- 但不要求必须死板出现某几个词

若第一段只是普通时局分析，则：

- 可以继续允许提交
- 但应被判成低质量 `omen`
- 更可能落入 `vague_or_ceremonial`

## 7. UI 建议

### 7.1 `设局嫁祸`

保留当前单输入框即可。  
因为它仍然是“对一个人说一句话，让他自己掉进局”。

但 helper copy 应更明确：

- “这类话要能诱他失言、失态或误判。”
- “重点不是让他怀疑别人，而是让他自己更像可疑之人。”

### 7.2 `谶纬`

建议在施计页出现专属布局：

- 输入框 1：`谶辞 / 征兆`
- 输入框 2：`解释 / 指向`

并配简短提示：

- “先给征兆，再解其意，最后指向最该警惕的人或势。”

## 8. 实现优先级建议

推荐顺序：

1. 先做 `设局嫁祸` 的专项 parse 字段与玩家定义
2. 再做 `谶纬` 的双段输入流程
3. 再更新样本库与 live balance harness
4. 最后再看是否需要调数值

## 9. 非目标

本设计暂不处理：

- `设局嫁祸` 的国力数值重平衡
- `谶纬` 的强度调整
- `离间` 的机制改造
- 战役平衡
- 外部势力线教学

这些仍应在后续独立议题中推进。
