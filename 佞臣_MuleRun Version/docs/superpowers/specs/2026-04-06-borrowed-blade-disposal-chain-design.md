# 《佞臣》借刀处置链设计

日期：2026-04-06

## 背景

当前《佞臣》的北周线已经形成一条较清晰的递进链路：

- `试探`：摸口风、探暗线、找心结
- `献策`：建立信任，并在特定语义下让目标人物得利而国家受损
- `谗言`：种下对具体人物的不满与疑虑
- `离间`：把关系裂缝推进到权力协作层
- `借刀`：理论上应是整条链路的收尾技

但现有系统里，`借刀` 仍停留在：

- 施计对象更信你
- 第二目标掉信任/忠诚
- 轻度 faction / nation 伤害

它并没有形成“借别人之手正式除掉某 NPC”的完整链路。

这也是之前测试里“角色都死不掉”的根因之一：不是样本不会玩，而是系统里根本没有一条面向朝臣 NPC 的借刀处置状态机。

## 现状诊断

当前项目里真正会触发 `isAlive = false` 的主要只有两类：

1. 玩家自己被朝臣纳入处置链后死亡  
   见：
   - `src/game/nationEngine.ts`

2. 外部势力叛乱失败后被平叛军剿灭  
   见：
   - `src/game/roundSettlement.ts`

而 `借刀` 本身在：

- `src/game/schemeEngine.ts`

里没有任何会让朝臣 NPC 进入死亡/清除/处置结果的逻辑。

结论：

- “朝臣 NPC 可死亡”目前并未形成系统闭环
- `借刀` 需要独立的“目标处置链”，不能再只当成一般关系打击计

## 设计目标

本次设计的目标不是让 `借刀` 变成“高分即秒杀”，而是让它成为一条高完成度权谋路线的收尾技：

- 没铺垫时，`借刀` 只能造成失势、断关系、加深风险
- 铺垫足够时，`借刀` 可以把目标推入正式处置链
- 只有高完成度、合时机、合对象时，`借刀` 才有机会真正除掉某 NPC

玩家体验目标：

- `试探 -> 献策 -> 谗言 -> 离间 -> 借刀` 的递进关系变得真实
- “除掉一个 NPC”应是顶级成果，而不是常规输出
- 不同对象、不同回合、不同铺垫程度，会导致完全不同的借刀结果

## 方案对比

### 方案 A：单次借刀直接判死

逻辑：

- `借刀` 成功
- trust 足够高
- parse 足够高
- 第二目标直接死亡

优点：

- 简单
- 爽点强

缺点：

- 太跳
- 削弱前置计谋的意义
- 不像朝堂权谋，而像数值斩杀

不推荐。

### 方案 B：借刀处置链

逻辑：

- 目标 NPC 有独立的“可处置度”
- 前置计谋负责推进该状态
- `借刀` 负责在合适窗口把“可处置”转成“被正式收拾”

优点：

- 最符合《佞臣》的玩法气质
- 能自然奖励整条权谋链
- 方便后续教学与回放解释

缺点：

- 机制会多一层状态
- 需要补 UI/反馈说明

推荐采用。

### 方案 C：只对少数关键 NPC 做剧情特例

逻辑：

- 某些固定人物在特定回合和条件下才会被借刀除掉

优点：

- 剧情感强

缺点：

- 系统性弱
- 不利于长期数值调优

适合二期强化，不适合作为底层方案。

## 推荐方案

采用 **方案 B：借刀处置链**。

## 核心状态机

为朝臣/宫廷中枢 NPC 新增轻量状态：

- `safe`：暂无明显处置风险
- `questioned`：已被怀疑、被盯上，但还没有真正孤立
- `isolated`：已经失去足够的政治遮护，进入“可被处理”边缘
- `disposable`：具备被正式收拾的政治条件

`dead` 不作为常驻状态字段，而继续沿用现有 `isAlive = false`。

也就是说：

- `safe/questioned/isolated/disposable` 管“可处置度”
- `isAlive` 管“是否已被除掉”

## 哪些 NPC 先支持这套链

首批只支持 5 名朝臣/宫廷中枢 NPC：

- 祖廷
- 宗艾
- 宇文棣
- 令狐律光
- 尉迟暮

理由：

- 都具备“被正式收拾/借刀清除”的政治合理性
- 都有明确的权力位置与关系网
- 有利于先把系统做稳，而不是一次铺满全部角色

## 各计谋如何推进处置链

### 试探

不直接推进处置链状态，但负责：

- 解锁暗线
- 获取心结
- 为后续计谋提供更高成功率与更高结构分

### 献策

不直接推进处置链状态，但能：

- 提高对“刀”的 trust
- 让出手者更愿意在后续出手

若是 `利人害国` 类型的献策，还能顺手制造局部权力失衡，为后续借刀创造环境。

### 谗言

主要负责把目标从 `safe` 推到 `questioned`。

成立条件：

- 明确指向具体关系对象
- 不是泛泛怀疑
- 能让施计对象开始把目标视为“不可靠/可疑”

### 离间

主要负责把目标从 `questioned` 推到 `isolated`。

成立条件：

- 裂缝不止停留在情绪层
- 已经影响权力合作、军令协作、名分站位或后勤节次

### 设局嫁祸

主要负责把“嫌疑回到目标本人”。

效果不是直接杀，而是：

- 提高该目标从 `questioned -> isolated`
- 或从 `isolated -> disposable` 的推进效率

它是“借刀前的最好铺垫技”之一。

### 谶纬

不是直接推进人际裂缝，而是提供：

- 名分裂缝
- 法统裂缝
- “此人继续在位会带来更大不祥/更大失序”的外壳

因此它可以给 `借刀` 增加一层“公域遮罩”。

### 借刀

真正负责把前面铺垫转成实质结果。

但不直接二元判“死/不死”，而是四档结果。

## 借刀的四档结果

### 1. 失败

出手者不上钩，甚至反感：

- trust 下降
- 暴露风险上升
- 目标处置链状态不动或反弹

### 2. 轻成

目标失势，但未被正式列入处置链：

- 目标掉 trust / loyalty / faction influence
- target 可能从 `safe -> questioned`
- 或保持 `questioned`

### 3. 重成

目标被正式推入处置链：

- `questioned -> isolated`
- 或 `isolated -> disposable`
- 同时产生更强的 faction / nation shock

### 4. 极成

目标被正式除掉：

- `targetNpc.isAlive = false`
- 生成专属 report
- 关系网与 faction 出现更大震荡

这应是高完成度路线的顶级成果，而不是常规结果。

## 借刀致死的核心判定

借刀能否极成，不只看本回合 parse，而是四项共同决定：

### 1. 出手者意愿

包括：

- 玩家对施计对象 trust 足够高
- 施计对象对目标有现成动机
- 施计对象具备足够执行能力

### 2. 目标可处置度

即目标在链路中的阶段：

- `safe`
- `questioned`
- `isolated`
- `disposable`

建议：

- 只有 `disposable` 才允许出现直接死亡结果
- `isolated` 最多进入“重成”

### 3. 公域遮罩

也就是：

- 这刀打下去能否在朝堂上说得过去

例如：

- 失职
- 擅权
- 越分
- 误军
- 名分不正
- 借灾异而失德

这部分应与 `proxyTransmission`、`frame`、`omen` 的输出联动。

### 4. 时局窗口

并非所有回合都适合动刀。

更适合的窗口：

- 清查、整饬、问责回合
- 战败、军令失序、后勤失灵回合
- 灾异、名分争论、法统波动回合

## 推荐的最小实现规则

为了先把系统做稳，建议第一版用下面这套硬规则：

- 若 `target.disposalStage < isolated`  
  `proxy` 不得触发死亡

- 若 `target.disposalStage === isolated`  
  `proxy` 最多打到“重成”，不直接死亡

- 若 `target.disposalStage === disposable`，且同时满足：
  - 出手者 trust 足够高
  - `proxyTransmission` 足够高
  - 当前回合属于可动刀窗口
  - 施计对象本身具备处置能力  
  才允许触发死亡

## 与现有系统的接法

### 1. relationship / structure 系统

当前关系断裂已经会触发结构冲击：

- `src/game/relationshipEngine.ts`

借刀处置链应复用这套基础，不另起一套关系系统。

### 2. roundSettlement

推荐在 `roundSettlement` 中维护：

- 每个目标 NPC 的 `disposalStage`
- 借刀结果 report
- 若触发死亡，则统一在这里落 `isAlive = false`

而不是在 `schemeEngine` 里直接硬改全局状态。

### 3. ending / intel / UI

一旦目标被除掉：

- `CourtView` 应显示 `已殁`
- 冯道之锦囊和回合播报可引用此结果
- 结局页 `npcFates` 可显示“死于借刀”类 fate

## 为什么之前测不出“借刀杀人”

根因不是样本不行，而是系统缺链：

- `借刀` 现在没有 NPC 处置状态机
- 没有从“怀疑/裂缝/背锅”推进到“可被除掉”的结构
- 也没有在 `proxy` 成功后把朝臣 NPC 真正写成 `isAlive = false`

所以玩家再会玩，也最多打出：

- 关系裂缝
- 失势
- 国力受损

而不会打出真正的“借刀除掉某人”。

## 推荐实施顺序

1. 给首批 5 名目标加 `disposalStage`
2. 让 `谗言 / 离间 / 设局嫁祸 / 谶纬` 以不同方式推进该阶段
3. 让 `借刀` 产出四档结果，而不是纯数值伤害
4. 最后再补 UI / 反馈 / live balance 样本

## 验证标准

第一版应满足：

- 无铺垫时，`借刀` 很难直接杀人
- 铺垫充分时，`借刀` 能稳定把目标推进到“重成”
- 高完成度路线下，首批 5 名 NPC 中至少部分人可以真实死亡
- 死亡结果能在 `CourtView / Ending / intel` 中被观察到

## 当前结论

`借刀` 不该被设计成“强一点的离间”，而应该成为整条北周权谋链的收尾技。  
要做到这一点，就必须补上朝臣 NPC 的“处置链”，而不是继续只加国力伤害或 trust 变化。
